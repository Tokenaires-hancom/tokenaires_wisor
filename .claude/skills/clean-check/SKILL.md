# 클린 코드 5원칙 검수

이번에 push될 변경이 루트 `CLAUDE.md`의 "클린 코드 5원칙"을 지켰는지 판정하고 **알려주기만 한다.**

## 절대 규칙

**공통 규칙은 루트 `CLAUDE.md`의 "검수 등급" 절에 있다** — 고치지 않는다, 항목을 전부 출력한다, 근거 없이 ❌를 달지 않는다. 여기에 옮겨 적지 않는다.

이 검수에만 해당하는 규칙은 하나다.

- **테스트를 돌리지 않는다.** "테스트가 있나"만 본다. "통과하나"는 PR에서 `check.yml`이 본다.

## 순서

**1. 이번에 나갈 변경을 구한다**

```bash
git rev-parse --abbrev-ref --symbolic-full-name '@{upstream}'
```

upstream이 있으면 `git diff @{upstream}..HEAD`, 없으면(첫 push) `git fetch origin develop` 후 `git diff origin/develop..HEAD`를 본다. 커밋 메시지는 같은 범위로 `git log`를 본다.

**2. 기준을 읽는다**

루트 `CLAUDE.md`의 "클린 코드 5원칙" 절. 변경된 디렉터리에 `CLAUDE.md`가 있으면 그것도 읽는다.

**3. 항목별로 판정한다**

| 질문 | 무엇을 보고 답하나 |
|---|---|
| 1 기능에 맞는 테스트가 있는가? | 새로 만들거나 크게 고친 소스에 대응하는 테스트 변경이 있나. 없으면 화면 파일인가(그렇다면 PR에 확인 방법이 적혔나) |
| 2 한 번에 한 가지만 고쳤는가? | 몇 개 파일·몇 개 영역(`apps/web`·`data-pipeline`·`persona_explain`·`supabase`)이 바뀌었나. 한 기능을 고치다 딸려온 변경이 섞여 있나 |
| 3 같은 일을 하는 코드가 한 곳에만 있는가? | 새로 추가된 코드가 이미 있는 것과 하는 일이 같나. 이름·구현이 달라도 같은 일이면 두 벌이다 |
| 4 처음 보는 방식이 들어갔는가? | 이 저장소에서 처음 보는 방식인가. 새 추상화나 트릭이 들어갔나. **여기만 "예"가 문제다** |
| 5 왜 그렇게 했는지가 기록으로 남았는가? | 커밋 메시지가 "무엇을"이 아니라 "왜"를 설명하나. 코드에 남겨야 할 제약·함정이 주석으로 있나 |

**등급은 루트 `CLAUDE.md`의 "검수 등급" 절을 따른다.** 2단계에서 이미 읽은 그 파일이다.

**4. 출력한다**

**배너 한 개, 표 한 개, 그 아래 ❌·⚠️만 자세히.** 판정 다섯 개가 한 화면에 들어와야
한다. 텍스트로 죽 늘어놓으면 코드를 못 읽는 사람이 스크롤하며 읽게 되고, 그때
진짜 지적 하나가 나머지 넷에 묻힌다.

- **배너 숫자는 표를 세서 쓴다.** 세지 않고 쓰면 표와 어긋나고, 그러면 맨 윗줄을
  아무도 믿지 않게 된다. 배너를 두는 이유가 사라진다.
- **표의 근거 칸은 ✅에도 채운다**(루트 `CLAUDE.md` 검수 등급 절). 못 채우면
  ✅가 아니라 `—`다.
- **표 아래 설명은 ❌·⚠️에만 붙인다.** ✅·`—`의 근거는 표 안에서 끝난다.
  전부 ✅·`—`면 표 아래는 비우고 "이번 변경에서 걸린 것 없습니다" 한 줄만 쓴다.
- 설명은 "무엇이 잘못됐다"가 아니라 **"그래서 나중에 뭐가 터진다"**로 쓴다.

원칙 이름은 루트 `CLAUDE.md`의 5원칙 제목을 그대로 쓴다. 표에 맞춰 줄이면
같은 원칙이 회차마다 다른 이름으로 불린다.

````markdown
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   클린 코드 5원칙 검수
   ❌ 1    ⚠️ 1    ✅ 2    — 1
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

| | 원칙 | 판정 | 근거 |
|:-:|---|:-:|---|
| **1** | 기능에 맞는 테스트가 있는가 | ⚠️ | `lib/masterMatch.ts`를 새로 만들었는데 짝이 되는 테스트가 없습니다 |
| **2** | 한 번에 한 가지만 고쳤는가 | ✅ | 파일 6개, `apps/web` 한 영역 안에서만 바뀌었습니다 |
| **3** | 같은 일을 하는 코드가 한 곳에만 있는가 | ❌ | `MasterComparisonInteractive.tsx` 88~120줄과 `MasterDiagnosisQuiz.tsx` 45~77줄이 거의 같습니다 |
| **4** | 처음 보는 방식이 들어갔는가 | — | 설정값 두 줄만 바뀌어서 새 방식이 들어갈 자리가 없습니다 |
| **5** | 왜 그렇게 했는지가 기록으로 남았는가 | ✅ | 커밋 본문에 unknown을 분모에서 뺀 이유가 적혀 있습니다 |

> **❌ 3 · 같은 로직이 두 파일에 있습니다**
> `MasterComparisonInteractive.tsx` 88~120줄과 `MasterDiagnosisQuiz.tsx` 45~77줄이 거의 같습니다.
> **→ 나중에 한쪽만 고치면 두 화면이 서로 다르게 동작합니다.**
> (CLAUDE.md 클린 코드 5원칙 3 — "복붙하지 말고 함수로 뽑습니다")

> **⚠️ 1 · 새 파일에 테스트가 없습니다**
> `lib/masterMatch.ts` 36줄이 새로 들어왔는데 대응하는 테스트가 없습니다.
> **→ 이 파일이 맞게 동작하는지 지금은 확인할 방법이 없습니다.**
````

**5. 검수를 마쳤다고 기록한다**

출력 후 아래를 실행한다. 이게 없으면 push가 계속 막힌다.

```bash
bash .claude/hooks/pre-push-check.sh --mark
```

기록한 뒤 사람에게 묻는다 — 지적을 고치고 갈지, 이대로 push할지.
