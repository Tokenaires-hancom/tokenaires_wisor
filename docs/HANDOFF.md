  “기괴하다”고 판단해 **폐기**했습니다. 버핏은 `scaleX(-1)` 좌우 반전 상태로
  왼쪽에 고정하며, 노드마다 따라가지 않고 세 번만 이동합니다: 1·2장은 2번 행

  4·5장과 전체 완료는 5번 행
  왼쪽(보정 없음). 첫 구간의 캐릭터와 말풍선 모두 소개 문장 아래에 놓입니다.
  캐릭터 위에는 `1장부터 시작하기` / `n장부터 이어서 하기`를 누를 수 있는 작은
  와인색 말풍선을 둡니다.
- **버핏 캐릭터에는 애니메이션과 hover 이동을 주지 않습니다.** 현재 왼쪽
  위치에서 `scaleX(-1)`로 좌우만 반전해 고정합니다. 새 학습자의
  `1장부터 시작하기`도 정지 상태입니다. 이미 1장을 마친 사용자의
  `2장부터 이어서 하기`(일반화해 `n장부터 이어서 하기`) 말풍선만
  `prefers-reduced-motion`이 아닐 때 1.8초 주기로 3px 위아래 이동합니다.
  말풍선 hover/focus에서는 기존의 2px 상승·옅은 와인 배경 반응을 유지합니다.
- 버핏의 위치는 화면별 임의 좌표가 아니라 위 세 구간의 앵커 행 왼쪽을
  기준으로 제한합니다. 인접한 가장 가까운 노드와 캐릭터 사이의 간격은
  1·2장에서는 두 노드 모두와 데스크톱·태블릿 40px, 모바일 34px 이상입니다.
  3장은 현재 노드와 데스크톱·태블릿 40px, 모바일 34px 이상이고, 4·5장은
  기존값(데스크톱·태블릿 20px, 모바일 14px)을 유지합니다. CTA 말풍선과는
  1·2장 데스크톱에서 소개문 아래 6px·캐릭터 위 12px, 태블릿·모바일에서
  소개문 아래 15.8px 이상입니다. 캐릭터 크기는 소수점 보간 없이 데스크톱
  190px, 1100px 이하 태블릿 150px, 640px 이하 모바일 124px의 세 단계입니다.
  `stand.webp` 원본은 506×720으로 선명도 여유가 충분합니다.
- 1100px 이하에서도 캐릭터는 숨기지 않습니다. 캐릭터 쪽 CTA만 숨기고 같은
  CTA를 현재 노드 위의 작은 말풍선으로 옮깁니다. 큰 모바일 버튼 디자인은
  더 이상 사용하지 않습니다.
- **챕터 읽기·퀴즈·정리 단계의 버핏은 본문 왼쪽에 둡니다.** 버핏의 오른손이
  본문과 선택지를 향하도록 `.chapter-stage`의 열 순서를 캐릭터→본문으로 바꿨고,
  모바일은 기존처럼 콘텐츠 위 중앙 배치를 유지합니다. `guide/great/nope/proud/aha`
  애니메이션은 투명 배경 WebP로 교체했습니다. 각 프레임은 80~90ms로 원본
  60~70ms보다 약 33% 느리고, 5개 합계는 1.45MB입니다. 이전 GIF 5개는 복구용으로
  `C:\Users\Har27\AppData\Local\Temp\wisor-buffett-original-gifs`에 옮겨 두었습니다.
- **챕터 화면은 넓은 화면에서 1080px 프레임을 사용합니다.** 그 안에서 왼쪽 152px은
  캐릭터 전용 거터, 24px은 분리 간격, 나머지는 최대 720px의 읽기·문항 칼럼입니다.
  제목·문항·진행 막대·하단 이동 영역은 본문 시작선에 맞춥니다. 상단 질문에서 진행 막대로
  넘어가는 구간과 하단 이동 영역은 세로 여백을 한 단계 압축했습니다. 캐릭터를 프레임 바깥으로 빼지 않아
  콘텐츠와의 연결감 및 중간 폭 화면의 안전성을 유지합니다. 860px 이하에서는 이 거터를
  없애고 기존의 캐릭터 위·본문 아래 단일 칼럼으로 전환합니다.
- 860px 이하에서는 세로 대가 레일을 한 줄 가로 스크롤 레일로 전환합니다.
  작은 화면에서도 두 줄로 접혀 배너를 아래로 밀지 않으며, 480px 이하에서는
  나머지 대가를 가로 스크롤로 탐색합니다. 640px 이하 헤더는 `Wisor` 보조

**미해결로 열려 있는 것:**

  아이디어가 필요한 지점입니다. 새 후보는 카드 높이·폭을 유지한 채

  손·머리 끝이 잘리지 않는지 브라우저에서 확인해야 합니다. 아직 적용하지
  않았고 사용자 확인이 필요합니다.

## 결정된 것 (뒤집기 전에 읽으세요)

- **기준 막대의 충족은 골드입니다. 버건디가 아닙니다.** 기준 막대는 스크리너와
  종목 상세에 나오는데, 그 화면에서 빨강은 가격 방향을 뜻합니다. 버건디는 붉은
  계열이라 충족 표시로 쓰면 제품이 하지 않기로 한 말을 하게 됩니다.
  버건디는 버튼과 배우기 화면 UI에만 씁니다.
- **골드와 황토는 색상환에서 가깝습니다.** 그래서 충족·미충족·미판정은 색이 아니라
  모양으로 갈립니다 — 단색 채움 / 빗금 / 점선 테두리. 이 구분을 없애지 마세요.
- **게임 요소는 파생 가능한 것까지만.** XP·레벨·진행률·완료 표시는 이미 저장된
  `lessonsDone`에서 계산합니다. 스트릭과 오늘의 목표는 `store.ts`에 필드 두 개를
  더하는 선까지. 하트(체력)·젬 상점·리더보드는 범위 밖입니다 — 리더보드는 서버가
  필요한데 Supabase가 아직 연결돼 있지 않습니다.
- **캐릭터 애니메이션 WebP는 높이 360으로 통일돼 있고 폭은 제각각입니다.** 일부러입니다.
  각 애니메이션을 캐릭터에 맞춰 잘라내서, 높이를 고정하면 표정이 바뀌어도 발이 같은 자리에
  놓입니다. 폭을 고정하거나 `object-fit: cover`를 넣으면 이 성질이 깨집니다.

## 함정

- **이 머신에 저장소 사본이 둘 이상 있습니다.** `Downloads\tokenaires_wisor-main`이
  그중 하나입니다. 개발 서버가 그 사본에서 떠서, 고치지도 않은 화면을 검증한 사고가
  있었습니다. 서버를 띄우면 어느 경로에서 도는지 먼저 확인하세요.
- **`~/.codex/.claude/launch.json`이 개발 서버 경로를 정합니다.** 저장소 안의
  `.claude/launch.json`이 아닙니다. 사본을 옮기면 이 파일도 같이 고쳐야 합니다.
- **개발 서버가 살아 있는 동안 `.next`를 지우면 서버가 깨집니다.**
  `Cannot find module './885.js'` 같은 오류가 나면 서버를 멈추고 `.next`를 지운 뒤
  다시 띄우세요. 순서가 중요합니다.
- **`npm run build`를 개발 서버(`npm run dev`)가 같은 `.next`를 쓰는 채로
  돌리면 위와 같은 `./885.js` 사고가 납니다.** 오늘 두 번 났습니다. CSS/컴포넌트만
  바꿨으면 `npm test`와 브라우저 확인으로 충분합니다 — `npm run build`는
  꼭 필요할 때만, 그것도 개발 서버를 잠깐 내리고 돌리세요.
- **브라우저 콘솔 버퍼가 재시작 전 오류를 계속 들고 있습니다.** 오류가 오래돼
  보이면 실제 요청 기록과 대조하고 나서 판단하세요.
- **바이너리 diff는 리뷰로 안 잡힙니다.** 캐릭터 이미지의 머리카락이 배경 제거
  과정에서 지워진 적이 있는데, diff에는 `Bin 0 -> 40690 bytes`로만 보였습니다.
  이미지를 바꿨으면 열어서 보세요.
