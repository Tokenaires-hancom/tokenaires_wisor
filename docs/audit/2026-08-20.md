**3. 같은 일을 하는 코드가 한 곳에만 있는가?** ❌

컴포넌트 사이에 복붙된 코드 블록은 없습니다. 공용 함수(`chapterKey` 등)를
제대로 나눠 쓰고 있습니다.

문제는 다른 곳입니다. **같은 제품 규칙("권유하지 않는다")을 검사하는 필터가
세 군데 있고, 세 개의 목록이 전부 다릅니다.**

```
data-pipeline/wisor_data/styles/base.py   BANNED_PHRASES  단어 11개
   → 배치가 만드는 점수 문구를 검사

apps/web/content/curriculum/validate.ts   BANNED          구 6개
   → 커리큘럼 본문만 검사

persona_explain/safety.py                 _RULES          정규식 5줄
   → LLM 챗봇 출력을 검사. "저평가"·"익절"·"천장"처럼 다른 둘에 없는 말이 들어 있음
```

→ 새 금지어를 한 곳에만 추가하면 나머지 두 화면은 그대로 통과시킵니다.
지금도 `저평가`는 챗봇에서만 막힙니다 — 점수 화면과 커리큘럼에서는 그대로 나갑니다.
(CLAUDE.md 클린 코드 5원칙 3 — "같은 로직이 두 곳에 있으면 나중에 AI가 한 곳만 고치고
나머지를 놓쳐서, 눈에 안 보이는 불일치가 생깁니다")

반론도 적어둡니다 — 세 곳은 언어와 실행 시점이 달라(파이썬 배치 / TS 빌드 / 파이썬 서버)
그냥 함수로 뽑을 수가 없습니다. 현실적인 최소한은 **목록을 데이터 파일(JSON) 하나로
두고 셋 다 그걸 읽는 것**이고, 그것도 무거우면 **왜 목록이 다른지를 적어두는 것**입니다.
교육 콘텐츠가 금지어를 설명해야 해서 web 쪽이 느슨한 건 의도로 보이지만,
그 의도가 어느 파일에도 적혀 있지 않습니다.

그리고 세 목록 중 **어느 쪽도 `components/`와 `content/masters.ts`를 보지 않습니다**(1부 7번).

**4. 처음 보는 방식이 들어갔는가?** ✅

이 저장소에서 여기서만 쓰는 방식은 찾지 못했습니다.

`import`에 `.ts`를 붙인 곳과 안 붙인 곳이 섞여 있는데 이유가 있습니다 —
`npm test`가 `node --test`로 직접 돌리는 파일은 확장자가 필요하고,
Next만 거치는 파일은 필요 없습니다. 규칙이 있으니 4번은 ✅이고,
그 규칙이 문서에 없다는 것은 5번 문제입니다.

**5. 왜 그렇게 만들었는지가 영역마다 기록으로 남아 있는가?** ⚠️

```

```

`persona_explain/`은 더 심합니다 — 설계 문서가 없는 정도가 아니라 **루트 `CLAUDE.md`의
"저장소 구조와 경계" 절에 아예 없습니다.** 그 절은 `apps/web`·`data-pipeline`·`supabase`·`docs`
넷만 적고 있는데, 실제로는 다섯 번째 영역이 있고 파일이 19개입니다.
→ 세션을 열면 이 영역이 존재한다는 사실 자체가 컨텍스트에 안 들어갑니다.
"4인 역할과 소유권" 표에도 담당이 없습니다.

→ 다음에 AI에게 스크리너나 점수 모델을 고치라고 할 때 넣어줄 맥락이 없습니다.

같은 이유로 위 두 가지도 기록이 없습니다 — 금지어 목록이 왜 둘로 갈렸는지,
import 확장자를 언제 붙이는지.
