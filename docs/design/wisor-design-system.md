# Wisor 디자인 시스템

> 상태: 전 서비스 공통 기준 · 2026-08-12
> 적용 범위: 홈, 배우기, 종목 찾기, 차트 실습, 내 학습, 향후 화면
> 하위 명세: [배우기 디자인 시스템](./learn-design-system.md)

## 1. 브랜드의 한 문장

**Wisor는 사용자가 기업과 가격을 스스로 관찰하고 판단 기준을 쌓도록 돕는 투자 학습 서비스다.**

매수·매도 신호를 내리는 금융 앱도, 어려운 정보를 과시하는 대시보드도 아니다. 화면은
사용자에게 “지금 무엇을 보고, 무엇을 다음에 하면 되는가”를 차분하고 명확하게 알려야 한다.

브랜드의 시각 언어는 다음 네 가지다.

- **흰 종이** — 복잡한 투자 정보를 숨 쉬게 하는 바탕
- **Gold** — 전진·완료·주 행동
- **Wine** — 현재 위치·선택·핵심 관찰
- **단색 바닥 그림자** — 학습 도구를 눌러 보는 촉감

이 조합은 듀오링고식 게임성의 명료함을 가져오되, 금융 교육에 맞게 절제한 결과다.

## 2. 디자인 원칙

| 원칙 | 실제 화면에서의 의미 |
| --- | --- |
| 관찰을 앞세운다 | 숫자·차트·기준은 결론을 강요하지 않고 사용자가 읽을 근거를 보여 준다. |
| 한 화면, 한 주 행동 | Gold 버튼 또는 Gold 상태는 한 화면에서 가장 중요한 다음 행동 하나에만 준다. |
| 구조가 장식보다 먼저다 | 번호, 진행 막대, 구분선, 표, 배지는 실제 정보 구조를 설명할 때만 쓴다. |
| 흰 공간은 정보 위계다 | 배경색 블록을 쌓기보다 여백과 얇은 선으로 덩어리를 나눈다. |
| 상태는 색만으로 말하지 않는다 | 완료·현재·오류는 색과 함께 아이콘, 테두리, 텍스트 또는 형태로 중복 표현한다. |
| 캐릭터는 안내자다 | 캐릭터는 내용과 다음 행동을 향하며, 정보·문항·차트를 가리지 않는다. |
| 움직임은 보상 또는 신호다 | CTA, 완료, 가벼운 눌림에만 사용한다. 장식적인 부유·반복 움직임은 금지한다. |

## 3. 디자인 토큰

### 3.1 색상: 의미를 먼저 정하고 색을 쓴다

| 토큰 | 값 | 의미와 사용처 |
| --- | --- | --- |
| `--paper`, `--surface` | `#FFFFFF` | 페이지 바탕, 카드, 입력 면 |
| `--surface-sunk` | `#F7F7F7` | 약한 비활성 또는 드롭 영역 |
| `--ink` | `#4B4B4B` | 제목, 본문, 기본 아이콘 |
| `--ink-soft` | `#777777` | 보조 설명 |
| `--ink-faint` | `#AFAFAF` | 메타, 기준일, 비활성 숫자 |
| `--line` | `#E5E5E5` | 기본 경계·구분선 |
| `--line-strong` | `#CFCFCF` | 비활성 깊이·더 강한 경계 |
| `--gold` | `#FFA000` | 주 행동, 완료, 시작, 전진 |
| `--gold-deep` | `#C67B00` | Gold 요소의 바닥 그림자 |
| `--gold-soft`, `--gold-line` | `#FFF4E0`, `#FFD08A` | Gold 보조 면·테두리 |
| `--wine` | `#C2183C` | 현재 위치, 활성 메뉴, 정답, 핵심 강조 |
| `--wine-deep` | `#92102C` | 워드마크, 짙은 강조 |
| `--wine-soft`, `--wine-line` | `#FCE9ED`, `#EFA9B7` | 선택 상태 면·보조 테두리 |
| `--ochre` | `#8A5A17` | 오답, 주의, 제한 사항 |
| `--ochre-soft`, `--ochre-line` | `#F5ECDD`, `#DCC49A` | 오답·주의성 면과 테두리 |

색의 역할은 고정한다.

- Gold는 **전진과 완료**다. Gold 버튼·배너·배지·아이콘을 한 화면에 모두 남발하지 않는다.
- Wine은 **현재·선택·정답·핵심 관찰**이다. 오류 자체는 Ochre를 쓴다.
- 회색은 정보 밀도를 낮추는 도구다. 비활성은 낮은 대비뿐 아니라 disabled 상태를 함께 제공한다.
- Gold 위 흰 글자는 대비가 낮다. 16px 이상, 700 이상인 주 행동 텍스트에만 허용한다.
  작은 설명문이나 메타 정보는 Gold 면 위에 올리지 않는다.

### 3.2 타이포그래피

```css
--sans: "Pretendard Variable", Pretendard, -apple-system, system-ui, sans-serif;
--mono: "Pretendard Variable", Pretendard, -apple-system, system-ui, sans-serif;
```

Wisor는 전체를 산세리프로 쓴다. serif·신문체·과장된 display 폰트는 금융 서비스의
권위를 빌리지만 Wisor의 학습 친화성과 맞지 않으므로 사용하지 않는다.

| 역할 | 기준 |
| --- | --- |
| 기본 본문 | 16px, line-height 1.7 |
| 읽기 문단 | 1.03rem, line-height 1.9, 최대 40em |
| 페이지 핵심 제목 | `clamp(1.9rem, 4.4vw, 3rem)`, 800, line-height 1.35 |
| 화면/챕터 제목 | `clamp(1.8rem, 4vw, 2.5rem)`, 800, line-height 1.3 |
| 섹션 제목 | 1.45rem, 800 |
| 카드 제목 | 1.12rem, 800 |
| 버튼 | 1rem, 700 |
| 보조 버튼·도구 | 0.9rem, 750 |
| 메타/eyebrow | 0.68rem, 자간 `0.16em`, `Ink faint` |

- 한글 제목·카드명에는 `word-break: keep-all`을 적용한다.
- 본문 폭과 컨테이너 폭을 구분한다. 데이터 표·문항 카드는 넓을 수 있지만 긴 문단은
  40em 전후로 제한한다.
- 밑줄·형광펜 강조가 필요하면 Wine 텍스트 + Wine soft inset shadow를 사용한다.
  여러 색 강조를 섞지 않는다.

### 3.3 간격·면·깊이

- 기본 간격 축: **4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64px**.
- 기본 모서리: `12px`. 카드·버튼·배너·입력에 공통 적용한다.
- 원형은 아바타, 진행 노드, 아이콘 버튼처럼 원형 자체가 의미일 때만 쓴다.
- 기본 카드 padding: 24px. 작은 도구·선택지는 12px 16px 내외.
- 얇은 구분선: 1px `--line`. 섹션 구분은 배경 블록보다 얇은 선과 32~48px 여백을 우선한다.

Wisor의 깊이는 blur가 아닌 **바닥 그림자**로 만든다.

| 대상 | 기본 깊이 | 눌림 |
| --- | --- | --- |
| 일반 카드 | `0 4px 0 var(--line)` | 필요 시 2px 하강 |
| Gold 주 버튼 | `0 4px 0 var(--gold-deep)` | 2px 하강 + 그림자 2px |
| Quiet 버튼 | `0 4px 0 var(--line)` | 2px 하강 |
| 작은 CTA 말풍선 | `0 3px 0 var(--wine-line)` | hover 시 5px |

큰 흐린 그림자, 유리 효과, 그라데이션 배경은 기본 언어가 아니다.

## 4. 전역 레이아웃

```
┌────────────────────────────────────────────────────────────┐
│  Wisor · 보조 문구                              전역 메뉴 │ 60px
├────────────────────────────────────────────────────────────┤
│                                                            │
│                     페이지별 콘텐츠 프레임                │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 4.1 컨테이너

| 컨테이너 | 최대 폭 | 적합한 화면 |
| --- | --- | --- |
| 기본 `.wrap` | 1080px | 종목 상세, 학습 경로, 분석 결과, 일반 콘텐츠 |
| 좁은 읽기 `.wrap-narrow` | 720px | 긴 설명, 설정, 집중형 폼 |
| 넓은 선택 프레임 | 1440px | 카드 레일, 비교, 대가 선택 |

공통 좌우 padding은 `clamp(20px, 5vw, 64px)`이다. 넓은 화면에서 콘텐츠를 뷰포트
끝에 붙이거나, 보조 레일을 fixed로 빼서 본문과 멀어지게 하지 않는다.

### 4.2 헤더

- 흰 배경, 하단 1px `Line`, sticky, 높이 60px.
- 워드마크: Wine deep, 1.6rem. 보조 문구는 0.6rem 회색.
- 메뉴: 0.98rem, 항목 간 24px, 활성 상태는 Wine 텍스트 + 하단 2px Wine 선.
- 640px 이하는 보조 문구를 숨기고 메뉴만 내부 가로 스크롤한다. body 가로 스크롤은 금지한다.

### 4.3 정보 위계의 기본 순서

모든 주요 페이지는 가능하면 이 순서를 따른다.

1. 맥락: breadcrumb, 작은 메타, 현재 위치
2. 판단 주제: 명확한 큰 제목
3. 한 줄 설명: 이 화면에서 관찰할 것 또는 할 일
4. 핵심 콘텐츠: 표·카드·차트·문항 중 하나
5. 다음 행동: Gold CTA 또는 진행 요소
6. 출처·기준일·제한: 흐린 고지

이 순서를 뒤집어 CTA를 먼저 내세우거나, 고지문을 핵심 콘텐츠보다 강하게 보이게 하지 않는다.

## 5. 범용 컴포넌트

### 5.1 버튼

| 종류 | 사용처 | 형태 |
| --- | --- | --- |
| Gold primary | 계속, 저장, 분석 시작, 다음 단계 | Gold 면, 흰 글자, 4px Gold deep 바닥 |
| Quiet secondary | 이전, 취소, 보조 탐색 | 흰 면, Wine 글자, 2px 회색 테두리 |
| Text action | 재시작, 상세 설정, 낮은 중요도 행동 | 배경 없이 Wine 또는 Ink soft 텍스트 |
| Icon action | 뒤로, 캐러셀 이동, 닫기 | 기능이 한눈에 보이는 40~46px 컨트롤 |

- 기본 버튼 padding: 12px 20px, radius 12px, 1rem/700.
- hover는 색 변화와 최대 2px 이동만 허용한다.
- active는 `translateY(2px)`와 바닥 그림자 축소로 촉감을 만든다.
- disabled는 회색 면·흐린 글자·`not-allowed`; hover 효과를 남기지 않는다.
- 한 화면에 primary는 하나가 원칙이다. 예외는 명확히 독립적인 두 작업이 있을 때뿐이다.

### 5.2 카드

```
┌──────────────────────────────┐
│  eyebrow / 상태               │
│  제목                         │
│  설명 또는 핵심 수치           │
│  ──────────────────────────  │
│  보조 행동                    │
└──────────────────────────────┘
```

- 기본 카드: 흰 면, 1px Line, 12px radius, 24px padding.
- 클릭 카드: hover 시 Wine line 또는 맥락색 테두리, 최대 2px 상승.
- 선택 카드: Wine soft 배경 + Wine line 테두리 또는 Gold 상태를 사용한다. 둘을 동시에
  강하게 쓰지 않아 선택 신호가 과해지지 않도록 한다.
- 카드 안에서 제목 → 설명 → 출처/행동 순으로 둔다. 카드 전체를 클릭할 때 안에 경쟁하는
  버튼을 중첩하지 않는다.

### 5.3 데이터 행·기준 막대·상태 배지

금융 정보는 표나 조밀한 숫자보다 **판단 기준의 상태**를 읽게 해야 한다.

- 데이터 행: 1px 하단선, 좌우 16px 간격, 위아래 17~18px padding을 기본으로 한다.
- 기준 막대: 통과 Gold, 불충족 Ochre 사선, 정보 부족 흰 면 + dashed 회색 선.
- 정보 부족은 실패와 다르다. `unknown`을 빨간색 또는 오답으로 표현하지 않는다.
- 배지·상태 라벨은 0.68~0.75rem, 작은 텍스트만으로 색 의미를 맡기지 않는다.
- 표가 좁은 화면을 넘으면 표 자체만 가로 스크롤 컨테이너로 감싸고, 페이지 전체는 넘기지 않는다.

### 5.4 폼·선택지·피드백

- 입력: 흰 면, 1px `Line strong`, 12px radius, 기본 텍스트 크기 0.92rem 이상.
- 선택지: 흰 면·1px Line·12px radius, padding 11px 14px, 항목 간 8px.
- 선택/정답: Wine line + Wine soft. 오답/주의: Ochre line + Ochre soft.
- 오류는 “잘못되었습니다”만 쓰지 않는다. 사용자가 다음에 확인할 기준 또는 수정 방법을 짧게 제시한다.
- 성공은 과한 confetti 대신 체크, 짧은 긍정 문장, Gold 또는 Wine 상태 변화로 충분하다.

### 5.5 구분선·고지·빈 상태

- 일반 rule: 1px Line, 기본 상하 40px. 콘텐츠가 이미 복잡하면 24~32px으로 압축한다.
- 기준일·출처·제한은 `disclaimer`: 상단 1px Line, 12~16px top padding, 0.78rem Ink faint.
- 빈 상태는 삽화보다 “왜 비어 있는지 + 할 수 있는 다음 행동”을 먼저 준다.
- 경고성 정보는 Ochre를 쓰며, 투자 행동을 권유하는 문장으로 바꾸지 않는다.

## 6. 캐릭터와 일러스트레이션

캐릭터는 Wisor를 인간적인 학습 도구로 만드는 서명 요소지만, 모든 화면에 억지로 넣지 않는다.

### 사용 기준

- **써야 할 때:** 단계형 학습, 첫 방문 안내, 완료 피드백, 비어 있는 학습 상태.
- **쓰지 않을 때:** 복잡한 데이터 표, 차트 분석 결과, 판단에 집중해야 하는 화면, 이미 시각 정보가 많은 카드.
- 캐릭터는 행동 또는 콘텐츠를 향한다. 손 방향과 시선이 반대라면 좌우 반전 또는 다른 포즈를 사용한다.
- 데스크톱에서는 콘텐츠 프레임 **안의 전용 거터**에 둔다. 뷰포트 끝에 fixed로 띄우거나
  본문 위에 absolute로 겹치지 않는다.
- 모바일에서는 정보 방해가 없을 때만 콘텐츠 위 중앙으로 옮긴다. 그렇지 않으면 숨긴다.

### 에셋 품질 규칙

- 애니메이션: 투명 배경 RGBA WebP. 흰 사각형 배경이 생기는 GIF/RGB 애니메이션은 사용하지 않는다.
- 정지 대체 이미지: 같은 캐릭터의 투명 WebP 또는 PNG를 준비한다.
- 모든 pose는 발 또는 기준점이 일관되도록 같은 높이 캔버스에서 export한다.
- `object-fit: cover`로 얼굴·손·발을 자르지 않는다. `contain`과 방향별 안전 여백을 사용한다.
- `prefers-reduced-motion: reduce`에서는 반복 애니메이션을 멈추고 정지 포즈로 바꾼다.

### 모션 규칙

- CTA: 1.8초 주기, 최대 3px 상하 이동처럼 작은 “다음 행동” 신호만 허용.
- hover: 최대 2~3px 이동, 150~180ms ease-out.
- 캐릭터 자체의 무한 부유·hover 흔들림은 사용하지 않는다.
- 완료 피드백은 색·체크·문구가 기본이며 애니메이션은 보조다.

## 7. 반응형 규칙

| 폭 | 구조 원칙 |
| --- | --- |
| 861px 이상 | 보조 레일·캐릭터 거터·2열 도구 등 병렬 구조 허용 |
| 641–860px | 보조 레일은 가로 스크롤, 2열은 필요 시 1열로, 캐릭터는 본문 위로 |
| 481–640px | 헤더 정보 축소, 카드 레일은 86vw 등 하나의 항목에 집중 |
| 480px 이하 | 보조 링크·장식은 우선 숨기고 핵심 행동·현재 상태·본문만 남김 |

반응형은 축소가 아니라 **구조 전환**이다.

- 세로 레일 → 가로 스크롤 레일
- 콘텐츠 옆 캐릭터 → 위 중앙 캐릭터 또는 숨김
- 2열 도구 → 1열
- 표 전체 → 표 컨테이너만 가로 스크롤
- 보조 CTA → 숨김 또는 현재 요소에 통합

검수 폭은 최소 1920 / 1280 / 860 / 640 / 390px이다. 모든 폭에서 body의 가로 overflow는 0이어야 한다.

## 8. 접근성·콘텐츠 톤

- 모든 keyboard focus는 Wine 2px outline + 2px offset.
- 상태는 색과 아이콘·테두리·텍스트 중 두 가지 이상으로 표시한다.
- motion preference를 존중한다.
- 아이콘만 있는 컨트롤은 `aria-label`을 제공한다.
- 버튼 라벨은 행동을 그대로 말한다: “계속”, “답 확인하기”, “기준 보기”.
- 투자 관련 문구는 관찰·비교·학습 언어를 사용한다. 매수, 매도, 목표가, 미래 가격을
  직접 지시·예측하는 어조를 UI에서 만들지 않는다.
- 어려운 용어는 설명 또는 체크 포인트와 함께 두고, 애매한 마케팅 문장으로 대체하지 않는다.

## 9. 새 화면을 만들 때의 설계 절차

1. 화면의 단 하나의 주 행동과 사용자가 관찰할 정보를 한 문장으로 쓴다.
2. 기본 프레임(720 / 1080 / 1440)을 고른다.
3. 제목 → 설명 → 핵심 콘텐츠 → 다음 행동 → 고지의 위계를 배치한다.
4. Gold와 Wine의 의미를 확인한다. Gold가 둘 이상이면 우선순위를 다시 정한다.
5. 캐릭터가 정말 행동 이해를 돕는지 확인하고, 아니라면 넣지 않는다.
6. 860px과 640px에서 어떤 구조가 사라지거나 전환되는지 먼저 정한다.
7. 구현 후 1920 / 1280 / 860 / 640 / 390px에서 overflow, 읽기 폭, focus, reduced motion을 확인한다.

## 10. 금지 목록

- 누런 배경을 기본 배경으로 깔지 않는다.
- Gold와 Wine을 동시에 큰 면적으로 경쟁시키지 않는다.
- 모든 카드에 gradient, glow, 큰 blur shadow를 넣지 않는다.
- 상태와 관계없는 원형 badge·pill을 남발하지 않는다.
- 캐릭터에 불투명 사각 배경을 붙이거나 콘텐츠와 겹치게 하지 않는다.
- 반응형에서 데스크톱을 단순히 축소하지 않는다.
- 금융 서비스처럼 보이게 하려고 지나치게 작은 글자·촘촘한 표·암색 대시보드를 기본값으로 삼지 않는다.
- 투자 결론을 내리는 카피를 버튼, 배너, 성공 메시지에 넣지 않는다.
