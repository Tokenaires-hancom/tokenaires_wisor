## 이 문서를 읽는 법

수치는 두 종류입니다. **저장소에서 직접 확인한 사실**과 **가정이 붙은 추정**입니다.
추정에는 계산식과 가정을 함께 적었습니다. 확인하지 못한 것은 비워 두고 `확인 필요`로 표시했습니다.
아직 결정되지 않은 사업 항목은 §14.3에 이유와 함께 모았습니다. 비워 둔 칸은 실수가 아닙니다.
기획 단계에서 받은 피드백과 그 대응은 §3.2에 있습니다.

## 1. 한 줄 요약

**Wisor는 종목을 추천하지 않습니다. 종목을 고르는 기준을 가르칩니다.**

일곱 명의 투자 대가가 각자 무엇을 보고 판단했는지를 다섯 장의 커리큘럼으로 배우고,
그중 정량화가 가능한 네 철학으로 미국 상장사 380개를 실제로 채점해 보여줍니다.
점수는 블랙박스가 아니라 **"8개 기준 중 6개 충족"** 처럼 전부 열려 있고,
사용자는 자신이 확인한 것을 학습노트로 남깁니다.

매수·매도 권유, 목표가, 미래 가격 전망은 제공하지 않습니다. 이것은 마케팅 문구가 아니라
빌드에서 실행되는 코드 제약입니다(§5.3).

## 2. 문제

### 2.1 답은 넘치는데 기준이 없다

개인투자자가 접하는 정보는 대부분 **결론 형태**로 도착합니다. "이 종목 지금 사라",
"목표가 상향", "AI 수혜주 TOP 5". 리딩방·유튜브·증권사 리포트·생성형 AI 요약까지,
답을 주는 채널은 계속 늘어납니다.

문제는 답이 부족한 게 아니라 **답을 고를 기준이 없다는 것**입니다.
기준이 없으면 다음 세 가지가 반복됩니다.

| 상황 | 지금 벌어지는 일 |
|---|---|
| 가격이 흔들릴 때 | 판단을 붙들 기준이 없어 시장 분위기를 따라간다 |
| 여러 정보가 충돌할 때 | 더 자신 있게 말하는 쪽을 고른다 |
| 손실이 났을 때 | 무엇이 틀렸는지 특정하지 못해 학습이 누적되지 않는다 |

생성형 AI는 이 문제를 완화하지 않고 **가속**합니다. 그럴듯한 결론의 공급량이
사람의 검증 능력보다 훨씬 빠르게 늘기 때문입니다.

### 2.2 배우려 해도 배울 곳이 마땅치 않다

- **책** — 『현명한 투자자』, 『전설로 떠나는 월가의 영웅』은 원칙을 주지만, 오늘 화면에 있는
  종목에 그 원칙을 대보는 단계로 이어지지 않습니다.
- **강의·뉴스레터** — 결국 종목 이야기로 수렴합니다. 판단의 재현 가능한 절차를 남기지 않습니다.
- **스크리너** — 조건 필터는 주지만, 왜 그 조건인지를 가르치지 않습니다. 숫자를 넣을 줄 아는
  사람에게만 유용합니다.

즉 **"철학 → 기준 → 실제 기업 판정 → 내 기록"** 을 한 줄로 잇는 제품이 비어 있습니다.

## 3. 해결 방식

Wisor는 네 단계를 한 서비스 안에서 연결합니다.

```
① 배운다            ② 적용한다            ③ 확인한다           ④ 남긴다
투자 대가 7명       같은 기준으로         기준별 실제 판정      학습노트에
× 5장 커리큘럼  →   미국 380개 종목  →   데이터·가중치를   →  판단 근거와
198개 확인 문항     자동 채점            전부 열어서 확인      남은 질문을 기록
```

핵심은 **③에서 멈춘다**는 것입니다. Wisor는 "그래서 사세요"를 말하지 않습니다.
사용자를 "살까 말까"가 아니라 **"무엇을 확인해야 하는가"** 로 데려가는 것이 제품의 정의입니다.

### 3.1 왜 이 경계가 자산인가

세 가지 이유입니다.

1. **규제** — 매수·매도 권유를 하지 않으면 유사투자자문 영역과의 거리가 유지됩니다(§13.1).
2. **신뢰** — 추천하는 순간 서비스의 가치는 적중률로 평가되고, 틀리면 사용자가 이탈합니다.
   가르치는 서비스는 적중률로 평가되지 않습니다.
3. **콘텐츠 수명** — 추천은 하루면 상하고, 판단 기준은 상하지 않습니다.

### 3.2 이 형태가 된 과정 — 받은 피드백과 대응

지금의 제품은 처음 구상 그대로가 아닙니다. 기획 단계에서 받은 피드백 여섯 가지가
제품을 바꿨고, 그 결과가 저장소에 남아 있습니다. 아래는 전부 **확인 가능한 결과**로만
적었습니다.

| # | 받은 피드백 | 어떻게 반영했는가 | 확인 위치 |
|---|---|---|---|
| 1 | 기획 배경에서 자료를 활용해 신뢰도를 높일 것 | 커리큘럼을 원전 기반으로 세우고 **1차 자료 22건**을 대가별로 화면에 노출 | `/learn/sources`, 각 커리큘럼의 `primarySources` |
| 2 | 대중 자료 말고 원전을 참조할 것 | 1·2차 자료를 화면에서 분리하고, 나아가 **문단마다 출처의 성격을 태깅** | `content/curriculum/types.ts` |
| 3 | 게이밍 요소 | 듀오링고식 퀴즈와 대가별 학습 경로·진도. 단 정답이 있는 것만 채점하는 3계층 문항으로 절제(§4.1) | `components/DuoQuiz.tsx`, `MasterPath.tsx` |
| 4 | 기술 스택 선정 이유를 밝힐 것 | 영역별 선택과 근거를 표로 명시 | §11.2 |
| 5 | 주요 API 명세와 전략(필요 데이터·데이터 구조) | 데이터 계약을 코드와 문서 양쪽에 고정 | §3.3 |
| 6 | 차트 분석 VLM이 실패할 때의 fallback 전략 | **fallback을 만들지 않고 기능을 제거했습니다** | 커밋 `e9055e5` |

**2번은 요구받은 것보다 한 걸음 더 갔습니다.** 출처를 나열하는 데 그치지 않고
본문 문단마다 세 종류 중 하나를 붙였습니다.

| 태그 | 뜻 | 개수 |
|---|---|---|
| `원문` | 그 사람의 책·주주서한·인터뷰에 실제로 있는 내용 | 66 |
| `정리` | 취지는 맞지만 문장은 이 과정이 요약·재구성한 것 | 30 |
| `창작` | 원문에 근거가 없고 교육을 위해 새로 만든 것 | 22 |

총 118개이며, **본문을 고치고 각주를 안 고치면 빌드가 실패합니다.**
"이 문장이 버핏의 말인지, 우리가 지어낸 설명인지"를 독자가 구분할 수 있게 한 장치입니다.
같은 화면에 "투자 철학과 매도 유형의 이름은 Wisor가 붙인 것이고 공식 명칭이 아니다"라는
문장도 함께 실려 있습니다.

**6번에 대한 답이 이 제품의 성격을 가장 잘 보여 줍니다.**

차트 이미지를 비전 모델로 해석하는 기능이 실제로 있었습니다. IP당 일일 호출 제한까지
붙여 운영했습니다. 그런데 fallback 전략을 설계하려니 답이 나오지 않았습니다.
**차트 해석은 틀려도 그럴듯해 보이기 때문입니다.** 그럴듯하게 틀린 해석은 학습
서비스가 내놓을 수 있는 가장 나쁜 산출물입니다.

그래서 대안을 만드는 대신 **기능을 삭제했습니다**(2026-08-12). 담당자 한 명의 영역이
통째로 사라졌고 그 자리는 지금도 공석입니다(§11.5).
**신뢰할 수 없는 출력을 가리는 fallback보다, 그 기능을 하지 않는 쪽을 골랐습니다.**
같은 판단이 피셔·막스·소로스를 점수화하지 않은 결정(§4.2)과 `unknown`을 그대로 두는
규칙(§5.2)에도 걸려 있습니다. **셋 다 "할 수 있는데 안 한 것"입니다.**

**함께 제안받은 도구와 순서**

- **토스증권 오픈 API** — 채택했습니다. 가격을 공식 오픈 API(`openapi.tossinvest.com`)에서
  받고, OAuth 토큰으로 인증하며 100종목씩 묶어 호출합니다. 380종목이 여덟 번으로 끝납니다.
  MCP는 이번 범위에서 쓰지 않았습니다 — 배치가 정해진 시각에 한 번 도는 구조라
  대화형 도구 연결이 필요하지 않았습니다.
- **개발 순서(학습 화면의 톤·틀 → 필요한 컴포넌트 → 업무 분담)** — 그대로 따랐습니다.
  `docs/design/wisor-design-system.md`와 `learn-design-system.md`로 톤과 틀을 먼저 고정한
  뒤 그 위에 컴포넌트 21개를 만들었고, 소유 영역을 4인으로 나눴습니다(§11.5).

### 3.3 데이터 계약

피드백 5번에 대한 답입니다. **어떤 데이터가 필요하고 어떤 구조로 흐르는가**를
문서가 아니라 코드로 고정했습니다.

**외부에서 무엇을 받는가**

| 원천 | 받는 것 | 호출 방식 |
|---|---|---|
| SEC Company Facts | 최근 5개 회계연도 재무(10-K) | 티커별 조회, 결과를 `data/fundamentals.json`에 캐시 |
| 토스증권 오픈 API | 현재가 | OAuth 토큰 · `/api/v1/prices` 100종목 배치 |
| Nasdaq 종목 API | 시가총액 | 별도 조회. 가격 × 주식수로 대체하지 않음 |

**전략의 핵심은 런타임에 외부 API를 부르지 않는다는 것입니다.**
배치가 미리 받아 `scores.json` 하나로 굳히고, 화면은 그 파일만 읽습니다.
그래서 외부 API가 죽어도 서비스는 멀쩡하고, 사용자 수가 늘어도 API 비용이 늘지 않습니다.
가격만 갱신할 때는 SEC를 다시 부르지 않는 `--mode prices` 경로가 따로 있습니다.

**화면에 무엇을 넘기는가** — `scores.json` 구조

```
scores.json
├─ generatedAt · dataSource · asOf{ price, financial }
├─ universe{ indexes, requested 517, included 380,
│            excluded[{ code, count, examples }] }   ← 뺀 이유까지 데이터로 남긴다
├─ styles[4]  모델 정의
│   └─ id · name · modelVersion · method · criteria[{ code, label, weight, detail }]
└─ companies[380]
    ├─ ticker · name · sector · price · marketCap · asOf
    ├─ metrics{ 15개 지표 }        ROIC·FCF마진·EV/EBIT·PEG …
    └─ scores{ buffett | graham | lynch | greenblatt }
        └─ score · passed · totalJudged · dataConfidence
           └─ criteria[{ code, label, weight, status, message, detail }]
                                            └ pass | fail | unknown
```

`status`가 세 값인 것이 이 계약의 핵심입니다. 현재 4개 모델 × 380종목의 판정
**6,494건 중 `pass` 2,998 · `fail` 2,966 · `unknown` 530**입니다.
**`unknown` 530건이 0으로 접히지 않고 끝까지 살아서 화면까지 갑니다**(§5.2).

**챗봇에는 무엇을 넘기는가**

프론트는 지표 값을 보내지 않고 `{ticker, persona}`만 보냅니다. 서버가 같은
`scores.json`에서 숫자를 꺼내 씁니다. **화면에 뜬 숫자와 챗봇이 말하는 숫자가 어긋날 수
없는 구조**이며, 계약은 `persona_explain/챗봇_API계약.md`에 프론트 담당자용으로
따로 정리돼 있습니다.

## 4. 지금 작동하는 제품

문서상의 계획이 아니라 **현재 저장소에서 빌드되고 배포되는 화면**입니다.
전체 435개 정적 페이지가 생성됩니다.

| 화면 | 경로 | 내용 |
|---|---|---|
| 홈 | `/` | 일곱 철학 소개, 제품이 무엇을 하고 무엇을 하지 않는지 |
| 배우기 | `/learn` | 일곱 대가의 학습 경로 목차 + 주식 기본개념 5단원 |
| 대가별 학습 | `/learn/masters/[slug]` | 대가별 업적, 원칙, 출처, 5장 경로 |
| 학습 장 | `/learn/masters/[slug]/[chapter]` | 전제 · 탐색 · 검증 · 처분 · 실패 5장 |
| 철학 비교 | `/learn/compare` | 같은 다섯 칸을 기준으로 일곱 철학 횡단 비교 |
| 점수 설명 | `/learn/scoring` | 점수가 어떻게 만들어지는지 |
| 출처 | `/learn/sources` | 커리큘럼 근거 자료 |
| 종목 찾기 | `/screener/[style]` | 네 정량 모델의 종목 결과 |
| 종목 상세 | `/stocks/[ticker]` | 기준별 실제 판정 데이터 · 가중치 · 용어 설명 · 학습노트 |
| 내 학습 | `/me` | 진도, 퀴즈 결과, 관심종목, 학습노트 |

### 4.1 커리큘럼 — 일곱 철학이 같은 다섯 칸을 공유한다

일곱 대가가 **같은 다섯 장**을 공유하는 것이 설계의 핵심입니다.
덕분에 "그레이엄의 처분 기준"과 "린치의 처분 기준"을 같은 자리에서 비교할 수 있습니다.

| 장 | 이름 | 묻는 것 |
|---|---|---|
| 1 | 전제 | 이 스타일은 시장에 대해 무엇을 가정하는가 |
| 2 | 탐색 | 무엇을, 어디서 찾는가 |
| 3 | 검증 | 사기 전에 무엇을 확인하는가 |
| 4 | 처분 | 언제까지 들고, 무엇이 팔게 하는가 |
| 5 | 실패 | 이 스타일은 어떻게 무너지는가 |

다루는 일곱 명: **버핏·멍거 / 그레이엄 / 린치 / 하워드 막스 / 필립 피셔 / 그린블랫 / 소로스**

문항은 세 계층으로 나뉩니다. 정답이 있는 것만 채점합니다.

| 계층 | 피드백 | 저장 | 왜 |
|---|---|---|---|
| `채점형` | 즉시 정오 + 풀이 | 정답률 | 계산·정의처럼 답이 하나인 것 |
| `첨삭형` | 점수 없이 "빠진 요소" 안내 | 축별 태그 | 사고의 구조를 묻는 것 |
| `기록형` | 없음. 3개월 뒤 재노출 | 프로필 원본 | 자기 성향은 채점 대상이 아니다 |

**현재 콘텐츠 규모(저장소 확인):** 7개 커리큘럼 × 5장 = 35장, 확인 문항 **198개**,
주식 기본개념 **5단원**. 커리큘럼 정합성 검사는 빌드 시점에 실행되며 실패하면 빌드가 멈춥니다.

### 4.2 스크리너 — 정량화 가능한 네 철학만

| 모델 | 방식 | 기준 수 | 점수가 산출된 종목 |
|---|---|---|---|
| Buffett 1.0 | 임계값 가중합 | 8개 (총 18점) | 312 / 380 |
| Graham 1.0 | 임계값 가중합 | 6개 | 289 / 380 |
| Lynch 1.0 | 임계값 가중합 | 6개 | 250 / 380 |
| Greenblatt 1.0 | 순위 합산 (마법공식 원식) | 2축 | 244 / 380 |

**피셔·막스·소로스는 일부러 점수화하지 않았습니다.** 피셔는 정성 탐문, 막스는 시장 수준의
신용·심리, 소로스는 가격과 자금 흐름의 변화가 핵심이라 기업 재무 데이터로 점수화하면 철학이

명시합니다. **점수화할 수 없는 것을 점수화하지 않는 것도 제품의 입장입니다.**

### 4.3 대가 페르소나 해설 챗봇

종목 상세에서 대가의 화법으로 지표를 **해설**하는 챗봇이 붙어 있습니다.
숫자는 배치가 계산해 넘기고 LLM은 해설만 합니다. 프론트는 지표 값을 보내지 않고
`{ticker, persona}` 만 보냅니다.

출력에는 금지표현 필터가 걸려 있고, 걸리면 `cleaned` 또는 `regenerate`로 처리합니다.
LLM에게 자유를 주되 **매수·매도·목표가·전망은 구조적으로 나올 수 없게** 만든 구성입니다.

> 정상 응답합니다. **끝에서 끝까지 연결돼 있습니다.**
>
> **콜드스타트 대응:** 챗봇이 별도 서비스라 유휴 상태에서 잠듭니다. 예전에는 사용자가

## 5. 점수는 어떻게 만들어지는가

경쟁 제품 대비 가장 설명하기 좋은 부분이라 따로 뗍니다.

### 5.1 블랙박스가 아니다

```
버핏 1.0 = 8개 기준의 가중합 (총 18점)

  자본 효율성(3점)      5년 평균 ROIC ≥ 12%
  수익성 지속성(2점)    5년 중 4년 이상 ROIC ≥ 10%
  현금흐름 지속성(3점)  5년 연속 잉여현금흐름 양(+)
  현금 창출력(2점)      FCF 마진 ≥ 10%
  부채 부담(2점)        순부채 / EBITDA ≤ 2.5배
  이자 감당력(1점)      영업이익 / 이자비용 ≥ 8배
  사업의 성장(2점)      매출 5년 CAGR ≥ 3%
  현재 가격(3점)        FCF 수익률 ≥ 4% 또는 EV/EBIT ≤ 자기 5년 중앙값

점수 = 충족 기준의 가중치 합 ÷ 판정한 기준의 가중치 합 × 100
```

사용자는 **기준 이름, 기준식, 그 기업의 실제 값, 판정 결과, 가중치와 비중**을 전부 볼 수
있습니다. 점수가 낮으면 어느 칸에서 깎였는지가 바로 보입니다. 이것이 학습이 일어나는 지점입니다.

### 5.2 없는 값을 0으로 채우지 않는다

이 제품에서 가장 중요한 데이터 원칙입니다.

- 판정할 데이터가 없으면 `fail`이 아니라 **`unknown`** 입니다.
- `unknown`은 점수 **분모에서도 빠집니다.** 판정 가능한 기준끼리만 비교합니다.
- `unknown`이 전체의 25%를 넘으면 점수를 만들지 않고 **`정보 부족`** 으로 표시합니다.
- 380개 중 점수가 나오지 않은 종목이 모델별로 68~136개 있는 이유가 이것입니다.
  **빈칸을 채워 커버리지를 늘리는 대신, 빈칸을 빈칸으로 두었습니다.**

재무 공시가 늦은 기업이 구조적으로 불리해지지 않게 하려는 설계입니다.
그린블랫 원식에서는 금융·유틸리티처럼 원식의 비교 대상이 아닌 업종을
`정보 부족`과 구분해 **`판정 대상 아님`** 으로 따로 표시합니다.

### 5.3 원칙이 코드로 강제된다

문서에 적힌 약속이 아니라 실행되는 검사입니다.

| 원칙 | 강제 방식 |
|---|---|
| 매수·매도 권유 금지 | `BANNED_PHRASES` 11개 표현(매수·매도·목표가·손절·추천·보장·확실·오를·내릴·급등·바닥). 점수 문구 생성 시 포함되면 **예외를 던져 배치가 실패**한다 |

## 7. 시장

### 7.1 확인된 앵커 수치

아래는 공개 출처에서 확인한 숫자입니다. 출처와 기준 시점을 그대로 붙입니다.

| 지표 | 값 | 기준 시점 | 출처 |
|---|---|---|---|
| 국내 투자자 **미국 주식 보관금액** | **2,000억 달러 (약 300조 원)** | 2026-05-14 | 예탁결제원 집계 보도 |
| 해외주식 보유 중 미국 비중 | 94% | 2025년 3분기 | 자본시장연구원 |
| 대미 금융자산 총액 | 1조 1,492억 달러 | 2025년 말 | 한국은행 발표 보도 |
| 주식거래활동계좌 수 | 1억 500만 좌 | 2026-03-29 | 금융투자협회 집계 보도 |
| 2026년 1~4월 활동계좌 순증 | 670만 좌 (월평균 168만) | 2026-04 | 위와 동일 |
| 토스증권 누적 가입자 / MAU | **860만 명 / 550만 명** | 2026-02 | 토스증권 발표 |
| 토스증권 해외주식 월 거래대금 | 30조 원 (점유율 1위) | 2026년 상반기 | 언론 보도 |

**해석의 한계를 먼저 적습니다.**
`주식거래활동계좌 1억 500만 좌`는 **계좌 수이지 투자자 수가 아닙니다.** 1인이 여러 증권사에
계좌를 열면 중복 집계됩니다. 시장 규모의 분모로 쓰기에 부적절합니다.
**국내 해외주식 투자자의 실제 인원 수는 공개 통계에서 확인하지 못했습니다.**
아래 추정은 이 한계를 안고 만든 것입니다.

### 7.2 시장 규모 추정

**두 개를 구분해서 봐야 합니다.** 아래 TAM은 *이 시장의 사람들이 판단 정보에 돈을
얼마나 쓰는가* — 시장의 지불 의사 크기입니다. **Wisor 자신의 매출 상한은 이것과 다르게
계산됩니다.** 사용자에게 과금하지 않고 광고로 운영하기 때문입니다(§14.1).
Wisor의 매출은 `트래픽 × CPM`인데 **국내 금융 분야 CPM을 확인하지 못해 계산하지
않았습니다**(부록 A.3). 아래 TAM은 "이 시장에 돈이 도는가"를 보는 용도입니다.

숫자만 던지지 않고 식을 보입니다. **`p`(유료 전환율)는 확인된 값이 아닌 가정입니다.**

```
TAM(국내, 투자 판단 학습·정보 서비스의 지불 의사 총량)
  = 주식 앱 활성 이용자 A × 유료 지출 의향 p × 연 ARPU

  A     = 550만 명   ← 토스증권 단일 MAU(2026-02). 전체 시장의 하한선이다.
                       키움 등 타 증권사 이용자를 더하면 커지지만, 중복 없는
                       합산치는 공개돼 있지 않아 보수적으로 하한만 쓴다.
  ARPU  = 60,000원 ~ 120,000원/년
          ← 국내 퀀터스 연 118,000원, 해외 Simply Wall St 연 약 20만 원(월 $10.95),
             Validea 연 약 45만 원(분기 $74.95), GuruFocus 연 약 75만 원($499).
             해외 서비스는 국내 개인 학습자의 지불 구간을 넘으므로 하단만 참조한다
          ※ 이 문서의 달러 환산은 전부 1 USD = 1,500원으로 통일한다.
            (§7.1의 2,000억 달러 ≈ 300조 원과 같은 기준)
  p     = 확인 불가. 아래 세 시나리오로 나눈다.
```

| 시나리오 | p | ARPU 6만 원 | ARPU 12만 원 |
|---|---|---|---|
| 보수 | 0.5% | 165억 원 | 330억 원 |
| 중립 | 2% | 660억 원 | 1,320억 원 |
| 낙관 | 5% | 1,650억 원 | 3,300억 원 |

**SAM (한국어로 미국 주식을 학습하려는 개인)**
미국 주식 보관금액 300조 원은 확인된 값이지만, 이를 인원으로 나누려면 1인당 평균
보유액이 필요하고 그 값은 공개돼 있지 않습니다. **인원 기반 SAM 산정은 보류하고,
증권사 제휴나 사용자 조사로 실제 인원을 확보한 뒤 확정할 것을 권합니다.**

**SOM (3년 내 도달 가능)**
현재 사용자 수 데이터가 없어 산정하지 않습니다(§14.3). 지어내는 대신 비웁니다.

**광고 모델에서 실제로 중요한 수치**
위 TAM보다 Wisor에 직접 걸리는 것은 **월 페이지뷰**입니다. 그리고 그 값은 지금
**측정되지 않고 있습니다.** 광고 단가를 논의할 근거가 생기는 시점이 곧 이 문서의
숫자가 채워지는 시점입니다(§12.1).

### 7.3 성장 동력

1. **해외주식 투자가 구조적으로 늘고 있다.** 대미 금융자산이 1조 달러를 넘었고,
   미국 주식 보관액은 300조 원대입니다.
   미국 비중 94%가 말해 주는 것은 **이미 해외주식을 하는 사람에 한해서는**
   Wisor의 미국 종목 커버리지가 그들 보유 종목의 거의 전부에 닿는다는 것입니다.
   *국내 개인투자자 중 몇 %가 해외주식을 하는지는 이 수치로 알 수 없고, 확인하지도
   못했습니다*(§7.1). 한국 주식 부재의 리스크는 §13.2에서 따로 다룹니다.
2. **투자 인구의 진입 속도가 빨라졌다.** 2026년 월평균 활동계좌 순증이 전년 대비 71% 증가했습니다.
   새로 들어온 사람일수록 판단 기준이 없습니다.
3. **생성형 AI가 결론의 공급을 폭증시켰다.** 검증되지 않은 결론이 늘수록 기준의 필요가 커집니다.
   이것이 Wisor 홈 화면의 서사("AI 시대의 투자원칙")와 정확히 겹칩니다.

### 7.4 역풍

- **학습은 거래보다 동기가 약합니다.** 사용자는 "배우겠다"보다 "종목 알려줘"에 훨씬 강하게 반응합니다.
  이것이 Wisor의 가장 근본적인 시장 리스크입니다.
- **증권사 앱이 무료로 유사 기능을 붙일 수 있습니다.** 토스증권은 이미 AI·커뮤니티를 결합 중입니다.
- **광고 모델은 트래픽이 선행 조건입니다.** 사용자가 모이기 전까지 매출이 0이고,
  학습 서비스의 트래픽 축적은 거래 서비스보다 느립니다(§14.1).

| 커리큘럼 콘텐츠 | **높음** | 7개 철학 × 5장 × 198문항을, 서로 비교 가능한 같은 골격으로 정리하는 작업이다. 자동 생성으로 대체되지 않고 시간이 정직하게 든다 |
| 제품의 절제 | **가장 높음** | 추천하지 않는 제품을 만드는 것은 기술이 아니라 의사결정의 문제다. 트래픽을 원하는 조직은 이 경계를 지키기 어렵다 |

세 번째가 실질적인 해자입니다. 앞의 둘은 돈과 시간으로 따라올 수 있습니다.

## 8. 경쟁

### 8.1 가장 가까운 서비스들

**Validea (미국)** — 가장 가까운 유사 서비스
버핏·그레이엄·린치·그린블랫·오쇼너시 등 **12개 이상의 대가 모델로 개별 종목을 채점**합니다.
Wisor와 발상이 거의 같습니다. AAPL 공개 화면 기준으로 오쇼너시 80% · 버핏 79% · 그레이엄 29% ·
린치 0% · 그린블랫 0% 처럼 **모델별 백분율 점수**가 나열됩니다.
요금은 **Standard 월 $29.95 · 분기 $74.95**(분기 결제 시 연 약 $300 ≈ 45만 원),
**Pro 월 $99.95 · 분기 $269.95**(연 약 $1,080 ≈ 162만 원),
**Institutional 연 $5,000**입니다.
→ **차이:** 공개 화면은 **모델 이름과 퍼센트 점수까지**이고, 어떤 기준에서 깎였는지는
그 화면에 없습니다(기준별 판정을 담은 유료 리포트의 내부 구성은 확인하지 못했습니다).
그리고 Validea에는 **그 기준을 가르치는 커리큘럼이 없습니다.** 린치 0%를 본 사용자가
왜 0%인지, 린치가 무엇을 보는 사람인지 배울 경로가 제품 안에 없습니다.
영어 전용입니다.

> **읽어 둘 만한 신호:** 가장 가까운 이 서비스가 대가 모델 채점 하나로 **연 45만 원**을
> 받고 있고 상위 플랜은 연 162만 원입니다. "대가의 기준으로 종목을 본다"는 수요에
> 지불 의사가 실재한다는 근거이며, 동시에 **그 가격대가 한국 개인 학습자에게는
> 진입 불가**라는 뜻이기도 합니다. Wisor가 무료로 가는 이유 중 하나입니다(§14.1).

**GuruFocus (미국)**
대가들의 실제 보유 종목을 추종하게 해 주고, 500개 이상의 조건으로 전 세계 9만여 종목을
거를 수 있습니다. `Buffett-Munger`, `Peter Lynch`, `Greenblatt 마법공식`, `Graham Net-Net`
같은 **이름 붙은 대가 스크리너**를 제공하며 각 스크리너의 조건은 튜토리얼에 서술돼 있습니다.

→ **차이:** 조건이 공개돼 있어도 `GF Value`, `사업 예측가능성 등급` 같은
**자체 산출 지표**에 기대고 있어 사용자가 값을 재현할 수 없습니다.
Wisor의 기준은 전부 공개 재무항목 위의 사칙연산이라 사용자가 손으로 계산해 볼 수 있습니다.
가격대도 개인 학습자가 진입할 구간이 아닙니다(Premium 연 $499 ≈ 75만 원).

**Simply Wall St (호주)**
`Snowflake`라는 5축(가치·성장·성과·건전성·배당) 시각화가 대표 기능입니다.

않습니다.** 그리고 다섯 축은 특정 대가의 철학이 아니라 일반적인 재무 건전성 분류입니다.
Wisor는 "그레이엄이라면 이 칸을 이렇게 본다"까지 갑니다.

**Stockopedia (영국)**
StockRanks라는 0~100 종합 순위가 핵심입니다. 월 £32/$45부터, 연 $200~600 구간.
→ **차이:** 종합 순위는 편리하지만 **여러 지표를 하나의 숫자로 뭉개기 때문에**
왜 그 순위가 나왔는지를 사용자가 재현할 수 없습니다. Wisor의 점수는 기준별로 분해돼 있고
각 칸의 가중치와 실제 값이 화면에 나옵니다.

**국내 퀀트 플랫폼 — 퀀터스 · 퀀트킹 · 젠포트 · 인텔리퀀트**
백테스트와 전략 실행이 중심입니다. 퀀터스는 연 118,000원부터 시작합니다.

→ **차이:** 이 범주의 언어는 **수익률**입니다. "이 전략의 CAGR이 몇 %"가 핵심 지표이고,
사용자는 좋은 전략을 고르는 법을 배우지 판단하는 법을 배우지 않습니다.
Wisor는 수익률 순위표를 만들지 않기로 결정했습니다(§12.3).

**토스증권 (국내, 무료)**

AI·커뮤니티를 결합하고 있습니다.
→ **차이이자 위협:** 무료이고 이미 사용자가 있습니다. 다만 증권사 앱의 종목 발굴은
인기·거래량·수익률 중심이고, **거래를 일으켜야 수익이 나는 구조**라 "천천히 배우고 덜

### 8.3 이 시장의 빈 자리

1. **대가 모델로 종목을 채점하면서, 그 기준을 가르치는 교재를 같은 서비스 안에 둔 곳이 없다.**
   Validea는 12개 모델로 채점하지만 커리큘럼이 없고, 투자 교육 콘텐츠는 데이터가 없습니다.
   **Wisor의 실질적 차별화는 "근거를 공개한다"가 아니라 "도구와 교재가 같은 화면에 있다"입니다.**
2. **한국어로 이 일을 하는 서비스가 없다.** 위 표에서 대가 철학을 다루는 세 서비스는 전부
   영어 전용이고, 한국어 서비스들은 전부 수익률이나 결론을 다룹니다.
3. **아무도 "이 기준은 판정할 수 없습니다"라고 말하지 않는다.**
   데이터가 없으면 대개 조용히 0점 처리되거나 종목이 목록에서 빠집니다.
   Wisor는 `unknown`을 화면에 남기고 분모에서 뺍니다. 이것을 하는 서비스를 찾지 못했습니다.
   **세 가지 중 가장 복제하기 어려운 것이 이것입니다.** 커버리지가 줄어드는 걸 감수해야 하기 때문입니다.

## 9. 차별화

### 9.1 세 가지

**① 도구와 교재가 같은 화면에 있다**

대가 모델로 종목을 채점하는 서비스는 이미 있습니다(Validea, GuruFocus). 없는 것은
**그 기준을 가르치는 교재가 같은 제품 안에 있는 경우**입니다.

Validea에서 "린치 0%"를 본 사용자는 거기서 멈춥니다. 왜 0점인지, 린치가 무엇을 보는
사람인지 배울 경로가 제품 안에 없습니다.
Wisor에서는 기준 이름 · 기준식 · 그 기업의 실제 값 · 판정 · 가중치 · 비중이 전부 펼쳐지고,
**그 기준이 왜 그 기준인지는 같은 서비스의 린치 5장 커리큘럼에 있습니다.**
사용자는 "72점"이 아니라 "8개 중 6개를 채웠고, 못 채운 건 가격과 성장이며, 가격 기준은
3점짜리라 크게 깎였다"를 보고, 그 다음 "린치는 왜 PEG를 보는가"로 넘어갑니다.

덧붙여 Wisor의 기준에는 **자체 산출 지표가 하나도 없습니다.** GuruFocus의 `GF Value`나
Stockopedia의 `StockRanks` 같은 합성 값을 쓰지 않고, 전부 공개 재무항목 위의 사칙연산입니다.
사용자가 손으로 검산할 수 있다는 뜻이고, 학습 서비스에서는 이것이 기능입니다.

**② 없는 값을 0으로 채우지 않는다**

380개 중 모델별로 68~136개는 점수가 나오지 않습니다. 커버리지를 낮추는 선택입니다.
경쟁 서비스라면 대부분 빈칸을 0으로 채우거나 종목을 조용히 뺐을 것입니다.
Wisor는 `unknown`을 화면에 남기고 분모에서 뺍니다.
**재무 공시가 늦은 기업을 구조적으로 불리하게 만들지 않기 위해서입니다.**
사용자에게는 "데이터가 없다"와 "기준에 미달한다"가 다른 정보라는 것 자체가 학습입니다.

**③ 추천하지 않는 것이 코드로 강제된다**

11개 금지 표현이 점수 문구 생성 단계에서 예외를 던지고, 위반하면 배치가 실패합니다.
LLM 해설도 같은 필터를 거치고 걸리면 재생성합니다. 주식 화면에서 빨강·초록을 쓰지 않습니다.
이것은 정책 문서가 아니라 **CI에서 실행되는 검사**입니다.
사람이 바뀌어도, 트래픽 압박이 와도 이 경계는 코드를 고쳐야만 넘을 수 있습니다.

### 9.2 가치 제안 한 문장

> **미국 주식을 들고 있는 한국 개인투자자**에게
> **일곱 대가의 커리큘럼과 380개 기업의 기준별 판정 데이터**를 한 화면에서 제공합니다.
> **결론을 파는 국내 서비스들과 다르게 추천하지 않고**,
> **점수만 주는 해외 대가 스크리너들과 다르게 그 기준을 한국어로 가르칩니다.**

### 9.3 이 차별화가 깨지는 조건

정직하게 적습니다. 다음 중 하나라도 하면 위 세 가지는 전부 무너집니다.

- 수익률 백테스트 순위표를 만든다
- 포트폴리오 수익률을 추적해서 보여 준다
- "이번 주 주목할 종목" 형태의 큐레이션을 시작한다
- 커버리지를 늘리려고 결측치를 추정값으로 채운다
- **광고 과금을 계좌개설·거래 성과에 연동한다**(§14.1)
- **화면에 표시된 특정 종목과 연결되는 광고를 싣는다**

여섯 다 단기 수치에는 즉시 도움이 되고, 여섯 다 제품을 다른 것으로 바꿉니다.
뒤의 둘은 수익모델을 정하면서 새로 생긴 조건입니다.

## 10. 타겟과 진입 전략

### 10.1 고객 세그먼트

세그먼트별 인원 추정치는 공개 통계로 확인되지 않아 비웠습니다(§7.1). 우선순위만 제시합니다.

| 순위 | 세그먼트 | 지금 쓰는 것 | 겪는 불편 | Wisor가 맞는가 |
|---|---|---|---|---|
| **1** | 미국 주식 2~5년차. 추천을 따라가 봤고 결과가 엇갈린 사람 | 증권사 앱 + 유튜브 + 커뮤니티 | 왜 샀는지 스스로 설명하지 못한다. 손실의 원인을 특정하지 못한다 | **가장 맞다.** 문제를 이미 자각하고 있다 |
| **2** | 가치투자 스터디·독서모임 참여층 | 책 + 엑셀 + 각자 정리한 노트 | 책의 원칙을 오늘의 종목에 대보는 단계가 수작업이다 | **맞다.** 커리큘럼이 그대로 스터디 교재가 된다 |
| 3 | 금융권 취업 준비생 | 재무제표 강의, 자격증 교재 | 지표는 외웠는데 실제 기업에 적용해 본 적이 없다 | 맞다. 다만 증권사 광고의 대상 고객은 아니라 광고 가치는 낮다 |
| 4 | 이제 막 시작한 초보 | 증권사 앱 | 용어부터 막힌다 | 부분적. `주식 기본개념 5단원`이 이 층을 받는다. 다만 이탈률이 가장 높을 것 |

**1번에 집중할 것을 권합니다.** 초보(4번)는 규모가 크지만 학습 동기가 약하고,
스터디층(2번)은 동기가 강하지만 규모가 작습니다. 1번이 규모와 동기가 함께 있는 유일한 층입니다.

### 10.2 진입 경로

**핵심 자산은 435개의 정적 페이지입니다.** 커리큘럼 35장과 종목 380개가 전부 서버에서
미리 만들어진 검색 가능한 문서입니다. 광고비가 아니라 콘텐츠로 유입을 만들 수 있는 구조입니다.

| 단계 | 활동 | 왜 |
|---|---|---|
| **1단계 (0~1개월)** | 운영 가능한 상태 완성(§12.1) 후 무료 전면 공개 + 측정 시작 | 사용자 과금이 없어 유사투자자문 신고 요건인 '대가'가 발생하지 않는다(§13.1) |
| **2단계 (1~3개월)** | 검색 유입 관측 + 스터디·독서모임 커뮤니티 제휴 | 세그먼트 2를 통해 세그먼트 1에 도달하는 것이 광고보다 싸다 |
| **3단계 (3~6개월)** | §14.2 지표의 기준선 확보 → 증권사 광고 영업 착수 | 트래픽 실적 없이는 광고 단가를 논의할 근거가 없다 |
| 이후 | 한국 주식 유니버스 또는 B2B(증권사·교육기관) | 둘 중 무엇이 먼저인지는 3단계 데이터로 결정 |

### 10.3 무료는 임시가 아니라 전략이다

사용자 과금은 로드맵에 없습니다. 광고로 운영하기 때문입니다(§14.1).
무료가 유지되면 두 가지가 따라옵니다.

1. **규제 거리** — 유사투자자문업의 첫 번째 요건인 '고객으로부터 받는 대가'가
   아예 성립하지 않습니다(§13.1). 뒤늦게 유료화하며 규제를 재검토할 일이 없습니다.
2. **유입 마찰 없음** — 학습 서비스는 첫 방문에서 가치를 증명해야 하는데,
   결제벽은 그 기회를 없앱니다. 435개 정적 페이지의 검색 유입이 곧바로 사용으로 이어집니다.

대신 광고 모델은 **트래픽이 선행 조건**이라, 측정을 시작하는 것이 첫 과제가 됩니다(§12.1).

## 11. 기술 구조

### 11.1 전체 구조

```
[SEC Company Facts]  [토스증권 가격]  [Nasdaq 시가총액]
         └──────────────┬──────────────┘
                        ▼
            data-pipeline (Python 배치)
            수집 → 지표 계산 → 품질 게이트 → 스타일 채점
                        ▼
              apps/web/lib/generated/scores.json   ← 유일한 경계
                        ▼
              apps/web (Next.js 15, 정적 생성 435p)
                        ▼
                      Render
              wisor-w0fu.onrender.com
                        │
        ┌───────────────┴───────────────┐
   lib/store.ts                   /api/persona → persona_explain
   (지금 브라우저 저장,             (Render 별도 서비스 · Python HTTP
    Supabase 교체 지점)              → OpenRouter gpt-5.4-mini)
```

### 11.2 선택과 이유

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | Next.js 15.5 · React 19 · TypeScript 5.7 | 정적 생성으로 435페이지를 미리 만든다. 종목·학습 페이지는 사용자별로 달라지지 않아 서버 렌더가 필요 없다 |
| 의존성 | **3개 (next, react, react-dom)** | UI 라이브러리·차트 라이브러리·상태관리 라이브러리를 쓰지 않는다. 번들과 유지보수 비용을 낮게 유지하고, 디자인 시스템을 CSS 토큰으로 직접 관리한다 |
| 데이터 배치 | Python 표준 라이브러리 중심 (3,003줄) | 외부 데이터 벤더 SDK에 묶이지 않기 위해. 공급자 교체가 파일 하나 교체로 끝난다 |
| 사용자 데이터 | Supabase (스키마 작성 완료) | 지금은 브라우저 저장. 교체 지점이 `lib/store.ts` 한 파일로 격리돼 있고 모든 함수가 이미 비동기다 |
| LLM | OpenRouter · `gpt-5.4-mini` | 해설만 시키므로 대형 모델이 필요 없다. 프로바이더 교체가 어댑터 한 곳 |
| 배포 | 웹·챗봇 서버 모두 **Render**의 별도 서비스 | **런타임이 다르다.** 웹은 Node(`next start`), 챗봇은 Python(`ThreadingHTTPServer`)이라 한 서비스에 넣으려면 두 런타임을 담은 Dockerfile과 프로세스 매니저가 필요하다. 플랫폼을 하나로 묶어 환경변수와 배포는 한곳에서 관리한다 |

**설계에서 가장 중요한 결정은 경계를 하나로 줄인 것입니다.**
화면 코드는 재무 원천을 직접 만지지 않고 `scores.json`만 읽습니다.
점수 모델을 바꿔도 화면은 계약된 형태만 보면 되고, 데이터 공급자를 바꿔도 화면은 모릅니다.

## 12. 로드맵

기간은 현재 팀 규모(3명 가동) 기준의 **제안**이며 확정된 일정이 아닙니다.

### 12.1 지금 ~ 1개월 · 운영 가능한 상태 만들기

제품을 새로 만드는 게 아니라 **이미 만든 것을 밖에 내놓을 수 있게** 하는 구간입니다.

- **분석 도구 연결 — 지금은 사용자 수조차 모릅니다.** 광고 모델의 선행 조건이고,
  §14.2의 지표를 재는 수단이며, 첫 4주가 기준선이 됩니다. **이 구간의 최우선입니다**
- Supabase 연결 (`lib/store.ts` 함수 본문 교체) — 기기 간 동기화, 사용자 데이터 영속
- 프론트 스모크 테스트 1개 (학습 → 퀴즈 → 스크리너 → 상세 → 노트 저장)
- 점수 문구를 코드+값으로 분리 — 프론트가 문구를 고칠 수 있게
- 검토자 2인의 "교육용으로 적절한가" 평가

### 12.2 1 ~ 3개월 · 학습이 이어지게 만들기

지금 제품의 가장 큰 약점은 **재방문 이유**입니다. 커리큘럼을 다 읽으면 끝납니다.

- `기록형` 문항의 3개월 뒤 재노출 (스키마와 `dueJournalEntries`는 이미 존재)
- 학습노트 복기 — 노트 작성 시점의 점수가 이미 굳혀 저장되므로, "그때 무엇을 보고
  판단했는가"와 지금을 대조하는 화면
- 배치 정기 실행 (가격 갱신은 SEC 재호출 없이 `--mode prices`로 분리돼 있음)

### 12.3 3 ~ 6개월 · 시장 확장

- **한국 주식 유니버스** — 가장 큰 요청이 예상되는 항목이자 가장 큰 작업.
  DART 공시 기반 공급자 추가가 필요하며, 공급자 인터페이스는 이미 분리돼 있음
- 증권사 광고 도입 (§14.1) — 3~6개월 구간의 트래픽 실적이 전제
- 대가 추가 또는 사용자가 자기 기준을 만드는 기능

> **의도적으로 하지 않을 것:** 매수·매도 신호, 목표가, 수익률 백테스트 순위표,
> 포트폴리오 수익률 추적. 마지막 항목은 요청이 들어와도 하지 않습니다.
> 수익률을 보여주는 순간 제품이 성과로 평가되기 시작하고, 그 방향으로 한 번 가면 되돌아올 수 없습니다.

## 13. 리스크

### 13.1 규제 — 사용자에게 과금하지 않으므로 요건이 성립하지 않는다

> 아래는 공개 자료를 정리한 것이며 **법률 의견이 아닙니다.** 서비스를 외부에 공개하기
> 전에 자본시장법 전문 변호사의 확인을 받아야 합니다.

**유사투자자문업의 성립 요건**은 세 가지가 함께 충족될 때입니다.

```
① 대가를 받고            ← 회비·이용료 등
② 불특정 다수에게        ← 특정 고객 대상이면 투자자문업(등록 대상)
③ 개별성 없는 조언을     ← 간행물·출판물·통신물·방송 등을 통해
   업으로 한다              금융투자상품의 투자판단·가치에 관하여
```

투자자문업(등록)과의 갈림길은 **사업 규모가 아니라 "대가를 받는지"와 "조언이 특정인을
향하는지"** 입니다. 무료 정보 제공에 그치면 신고 대상으로 보기 어렵지만,
**회비나 이용료를 받는 순간 신고 의무가 발생할 수 있습니다.**

**Wisor의 현재 위치**

| 요건 | 현재 상태 |
|---|---|
| ① 대가 | **해당 없음** — 현재 무료 |
| ② 불특정 다수 | 해당 (웹 공개) |
| ③ 투자판단에 관한 조언 | **다툼의 여지가 있는 지점** |

③이 핵심입니다. Wisor는 매수·매도를 권하지 않지만 **종목별 점수를 제시**합니다.
점수 제시가 "투자판단 또는 가치에 관한 조언"에 해당하는지는 해석의 문제이며,
**이 문서에서 단정할 수 없습니다.** 다만 방어 논리는 이미 제품 안에 구축돼 있습니다.

- 금지 표현 11개가 코드로 차단되어 권유성 문구가 산출물에 들어갈 수 없음
- 점수는 공개된 기준식의 기계적 판정 결과이며 그 기준식 전체가 화면에 표시됨
- 화면 문구가 관찰과 확인 사항까지만 서술하도록 설계됨
- 목표가·수익률·미래 전망을 일절 산출하지 않음

**결론과 행동**

1. **①이 성립하지 않습니다.** 수익모델을 광고로 정했고 사용자에게 과금하지 않기로 했기
   때문입니다(§14.1). 유료화 계획이 로드맵에 없으므로 이 요건은 앞으로도 성립하지 않습니다.
2. **대신 다른 규제가 적용됩니다.** 광고는 유사투자자문이 아니라 금융소비자보호법의
   영역입니다. §13.3에서 따로 다룹니다.
3. 참고로 감독 강도는 높아지는 추세입니다. 금융감독원의 유사투자자문업자 점검에서
   2024년 745개사 중 112개사·130건, 2025년 289개사 대상 133건의 위법이 적발됐고
   미등록 투자자문업이 위반 유형의 12.3%를 차지했습니다.
   **규제를 피해 다니는 설계가 아니라, 애초에 걸릴 일을 만들지 않는 설계가 필요합니다.**
   Wisor는 이미 그렇게 만들어져 있습니다.

### 13.2 제품·기술 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **재방문 이유 부족** — 커리큘럼을 다 읽으면 끝난다 | 높음 | §12.2가 이 문제만 다룬다. 기록형 재노출과 노트 복기가 핵심 |
| **미국 주식만 다룬다** — 한국 종목 요청이 확실히 나온다 | 높음 | 공급자 인터페이스가 분리돼 있어 DART 공급자 추가로 대응. 다만 작업량이 크다 |
| **가격 데이터 재배포 제약** | 중간 | 현재 화면은 종가와 기준일을 함께 표기하는 학습 용도. 상업적 배포 조건 확인 필요 |
| **LLM 해설의 이탈** | 중간 | 금지어 필터 + 재생성 + 지표를 프론트가 보내지 않는 구조로 3중 차단 |
| **사용자 데이터가 브라우저에만 있다** | 중간 | 캐시를 지우면 학습 기록이 사라진다. §12.1 Supabase 연결로 해소 |
| **점수를 추천으로 오독** | 중간 | 화면 문구·색 규칙·금지어 코드로 방어 중. 사용자 조사로 실제 오독률 확인 필요 |
| **1인 공석** | 중간 | 4번 영역 재배정 필요 |

### 13.3 광고 규제 — 유사투자자문과는 다른 영역이다

> 여기도 법률 의견이 아닙니다. 실제 광고 계약 전에 확인이 필요합니다.

수익모델을 광고로 정하면서 적용 법령이 바뀝니다. 자본시장법의 유사투자자문업이 아니라
**금융소비자보호법의 금융상품 광고 규제**가 걸립니다.

| 쟁점 | 내용 | Wisor의 대응 |
|---|---|---|
| **광고 주체** | 금소법 제22조상 금융상품판매업자등이 **아닌 자**의 금융상품 광고는 원칙적으로 금지 | 광고 주체는 증권사로 두고 Wisor는 매체 역할만 한다 |
| **표시 의무** | 온라인 매체 광고 시 **직접판매업자의 확인을 받았다는 표시**가 필요 | 광고 영역에 표시를 넣는다 |
| **중개 해당 여부** | 금융위는 플랫폼이 **판매실적에 비례해 수수료를 받는 경우** 등 상품 판매에 적극 관여하면 중개로 판단 | **노출 기반 정액만 받는다.** CPA·거래 연동을 받지 않으므로 중개 요건에서 벗어난다 |
| **비교·추천 기능** | 상품을 비교·추천하거나 맞춤형 제안을 하면 중개 논란 | Wisor는 금융상품을 비교·추천하지 않는다. 종목 점수는 금융상품 추천이 아니다 |

**세 번째 줄이 이 모델의 안전핀입니다.** 과금 단위 하나가 광고대행과 중개업의 경계를
가르고, 동시에 제품 정체성의 유지 여부도 가릅니다(§14.1). 두 문제의 답이 같습니다.

**남은 리스크:** 종목 점수를 제공하는 화면에 증권사 광고가 함께 노출되는 것 자체를
감독당국이 어떻게 보는지는 확인하지 못했습니다. 화면 내용과 무관한 일반 광고로 한정하는
것이 현재의 대응이며(§14.1 준수 조건 4), 실제 계약 전 확인이 필요합니다.

## 14. 수익모델과 남은 결정

### 14.1 어떻게 지속하는가 — 노출 기반 증권사 광고

**사용자에게 돈을 받지 않습니다. 증권사 광고로 운영합니다.**
단, **노출 기반 정액 광고만 받고 성과 연동 수수료는 받지 않습니다.**

**왜 사용자 과금이 아닌가**

두 가지 이유입니다. 하나는 규제입니다. 유사투자자문업의 성립 요건 중 첫 번째가 '고객으로부터
대가를 받을 것'인데(§13.1), 사용자에게 과금하지 않으면 이 요건이 아예 성립하지 않습니다.
다른 하나는 진입장벽입니다. 학습 서비스는 첫 방문에서 가치를 증명하기 어려운데,
결제벽이 있으면 증명할 기회 자체가 사라집니다.

**왜 성과 연동이 아닌가 — 이것이 이 모델의 핵심입니다**

계좌개설 건당 과금(CPA)이나 거래 연동 수수료를 받으면 **Wisor의 수익이 사용자의 거래량에
비례하게 됩니다.** 그 순간 §8.1에서 증권사 앱의 한계로 지적한 구조를 Wisor가 그대로
갖게 됩니다. "천천히 배우고 덜 거래하라"고 말하면서 거래에서 돈을 버는 서비스는
오래 버티지 못합니다.

노출 기반 정액이면 수익은 **학습 트래픽**에 비례합니다.
사용자가 커리큘럼을 다 읽고 아무것도 사지 않아도 수익은 같습니다.
**광고를 받되 거래에 연동된 과금은 받지 않는다** — 이 한 문장이 모델의 전부입니다.

부수적으로 규제도 여기서 갈립니다. 금융위는 플랫폼이 **판매실적에 비례해 수수료를 받는 경우를
'중개'로 판단**해 왔고, 중개에 해당하면 금융상품판매대리·중개업 등록이 필요합니다.
정액 노출 광고는 광고대행의 영역입니다.

**준수 조건**

| # | 조건 | 근거 |
|---|---|---|
| 1 | 광고 주체는 증권사이고 Wisor는 매체다 | 금소법 제22조 — 금융상품판매업자등이 아닌 자의 금융상품 광고는 원칙적으로 금지 |
| 2 | 광고에 직접판매업자의 확인을 받았다는 표시를 넣는다 | 온라인 매체 광고 시 표시 의무 |
| 3 | 판매실적 연동 수수료를 받지 않는다 | 중개 해당 회피 |
| 4 | 화면에 표시된 특정 종목이나 매매 행동과 연결되는 광고는 싣지 않는다 | 점수 옆의 종목 연계 광고는 권유로 읽힌다. 화면 내용과 무관한 일반 광고는 제약하지 않는다 |

**선행 조건 — 정직하게 적습니다**

광고 모델은 **트래픽이 있어야 성립합니다. 그런데 현재 트래픽은 측정조차 되고 있지 않습니다.**
분석 도구가 연결돼 있지 않기 때문입니다(§14.3). 따라서 이 모델의 첫 번째 과제는
광고 영업이 아니라 **측정을 시작하는 것**이고, 그래서 §12.1에 넣었습니다.
데모데이 시점에서 이것은 수익이 아니라 **검증되지 않은 계획**입니다.

### 14.2 성공 지표

이 제품은 거래를 일으키지 않으므로 **거래 관련 지표를 쓰면 안 됩니다.**
광고 모델이라고 해서 이 원칙이 바뀌지 않습니다. 계좌개설 전환율이나 거래 유도 지표는
측정 대상에서 제외합니다. 측정하기 시작하면 그쪽으로 제품을 최적화하게 되기 때문입니다.

| 지표 | 무엇을 말해 주는가 |
|---|---|
| 커리큘럼 장 완료율 (35장 중) | 콘텐츠가 실제로 읽히는가 |
| 학습노트 작성 사용자 비율 | ③에서 ④로 넘어가는가 — **제품의 핵심 전환** |
| 노트당 평균 `open_questions` 수 | "확인할 것"을 스스로 만들어내는가 |
| 3개월 뒤 기록형 문항 재응답률 | 재방문이 만들어지는가 |
| 스크리너 → 종목 상세 → 기준 펼침 비율 | 점수만 보고 나가는가, 근거를 여는가 |

마지막 지표가 가장 중요합니다. **점수만 보고 나간다면 이 제품은 추천 앱과 다르지 않습니다.**

목표 수치는 정하지 않았습니다. 기준선이 없는 상태에서 정한 목표는 근거가 없습니다.
측정을 시작한 뒤 첫 4주 값을 기준선으로 삼는 것을 제안합니다.

### 14.3 아직 정하지 않은 것과 그 이유

지어낼 수 있었지만 지어내지 않은 항목입니다.

| 항목 | 상태 | 왜 지금 정하지 않았는가 |
|---|---|---|
| **광고 단가·재고** | 미정 | 트래픽 데이터 없이 산정한 단가는 숫자놀이다. 측정 후 결정 |
| **현재 사용자 수** | **측정 안 됨** | 분석 도구가 연결돼 있지 않다. §12.1의 최우선 과제 |
| **광고주 접촉 여부** | 없음 | 트래픽 실적 없이 증권사와 논의할 근거가 없다 |
| **법인 설립·고용 형태** | 미정 | 발표 이후 지속 여부에 따라 결정 |
| **한국 주식 확장 시점** | 미정 | 작업량이 커서(§13.2) 팀 지속 여부가 정해진 뒤 결정 |

소유 영역은 문서로 고정돼 있고(§11.5), 데이터 검수만 전원이 리뷰합니다.

## 15. 요약

- Wisor는 **이미 작동하는 제품**입니다. 435페이지, 미국 380개 종목 실데이터,
  198개 확인 문항, 테스트 215개 통과.
- 제품의 정의는 기능 목록이 아니라 **경계**입니다. 추천하지 않고 가르칩니다.
  그 경계가 문서가 아니라 실행되는 코드로 지켜집니다.
- 대가 모델로 채점하는 서비스는 해외에 있습니다(Validea·GuruFocus). **점수 옆에 교재를
  두고, 한국어로, 판정 못 하는 칸을 판정 못 한다고 말하는 서비스는 찾지 못했습니다**(§8.3).
- 남은 것은 새 기능이 아니라 **운영 가능한 상태로 만드는 일**입니다(§12.1).
- 지속 방식은 **노출 기반 증권사 광고**입니다. 사용자에게 과금하지 않고, 계좌개설·거래에
  연동된 과금도 받지 않습니다. **수익이 거래량이 아니라 학습 트래픽에 비례하도록**
  과금 단위를 고른 것이고, 그 선택이 규제 경계도 같이 정리합니다(§14.1·§13.3).
- 다만 **트래픽은 아직 측정조차 되고 있지 않습니다.** 이 모델은 현재 수익이 아니라
  검증되지 않은 계획이며, 측정을 시작하는 것이 첫 과제입니다(§12.1).

  §7.2의 SAM을 비운 이유입니다.
- **유료 전환율 `p`** — 국내 투자 정보 서비스의 전환율 벤치마크를 확인하지 못했습니다.
  시나리오 세 개로 대체했습니다. Wisor 매출과 직결되는 값은 아닙니다(§7.2).
- **Validea 유료 리포트의 내부 구성** — 공개 화면은 모델별 백분율 점수까지만 보여 줍니다.
  유료 리포트에 기준별 판정이 있는지는 확인하지 못했습니다. §8.1의 서술은 공개 화면 기준입니다.
- **Simply Wall St의 한국어 지원 여부** — 공식 요금제 페이지에 언어 선택이 없음을 확인했으나,
  앱 내 지원 여부까지는 확인하지 못했습니다.
- **국내 퀀트 플랫폼의 사용자 규모** — 공개돼 있지 않습니다.
- **국내 투자 교육 시장 규모** — 독립적으로 집계된 통계를 찾지 못했습니다.
- **Wisor의 현재 사용자 수** — 측정 도구가 연결돼 있지 않습니다.
- **국내 금융·증권 분야 광고 단가(CPM)** — 확인하지 못했습니다. §14.3에서 광고 단가를
  비운 이유입니다.
- **종목 점수 화면에 증권사 광고를 노출하는 것에 대한 감독당국 판단** — 유사 사례를
  찾지 못했습니다. §13.3의 남은 리스크입니다.
