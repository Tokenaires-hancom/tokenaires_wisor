# 학습 경로 중심 화면 개편 — 설계

작성일 2026-08-10 · 레퍼런스 듀오링고 · 기준 커밋 `d237459`

---

## 목표

화면을 **기능 단위에서 학습 단계 단위로** 다시 배치한다. 이 문서는 와이어프레임을 그리기 위한 뼈대이고, 각 화면 내부의 배치는 다루지 않는다(2단계).

개편에 착수한 이유는 네 가지가 함께 지적됐기 때문이다 — 학습 흐름이 끊긴다, 첫인상이 약하다, 정보가 너무 많다, 쓸 기능이 모자란다. 네 가지를 개별로 고치는 대신 **경로**라는 축 하나를 세우고 나머지를 딸려 오게 한다.

## 지금 상태 (2026-08-10)

| | 수 |
|---|---|
| 라우트 | 11개 |
| 정적 생성 페이지 | 약 430개 (종목 380 + 마스터 챕터 35 + 차트 단원 5 + 스크리너 4 + 고정 6) |
| 학습 커리큘럼 | 대가 7명 × 5장 |
| 점수 모델 | 4개 (버핏·그레이엄·린치·그린블랫) |
| 네비게이션 항목 | 4개 |

**7 대 4 비대칭이 이 개편의 핵심 제약이다.** 막스·피셔·소로스는 커리큘럼은 있지만 점수 모델이 없다. `masters.ts`의 `SCORABLE_MASTERS`가 이 구분을 이미 코드로 들고 있고, `/screener/[style]`의 `generateStaticParams`가 여기서 나온다. 즉 **`/screener/marks` 라우트는 존재하지 않는다.**

## 범위

**1단계 (이 문서)** — 화면 구조와 이동 경로를 확정한다. 어떤 화면이 있고 무엇이 무엇으로 이어지는가.

**2단계 (별도 작업)** — 화면별 와이어프레임. 각 화면 안에 무엇이 어디에 놓이는가.

**범위 밖** — 시각 디자인, 색·활자 변경, 데이터 파이프라인, chart-api.

## 결정 사항

### 1. 경로를 학습의 중심 화면으로 올린다

대가를 고르면 5장이 세로로 이어지는 경로를 만든다. `CHAPTER_SLOTS`가 이미 고정 5단계(전제·탐색·검증·처분·실패)이고 7명 전원이 이 순서를 공유하므로, 경로의 데이터는 이미 코드에 있다.

네비게이션의 **경로** 항목이 이 화면을 가리킨다. 흐름은 경로가 구조로 보장하고, 한 화면이 한 단계만 맡으니 정보량이 준다. 네 번째 문제(기능 부족)는 4번 결정의 검색이 맡는다.

**루트(`/`)를 경로로 대체할지는 2단계에서 정한다.** 지금 홈은 서비스 소개(주장문 · 대가 그리드 · 두 렌즈 설명 · 결과 미리보기)이고, 경로로 갈아끼우면 첫 방문자가 이 제품이 무엇인지 알 수단이 사라진다. 반대로 소개를 그대로 두면 재방문자가 매번 소개를 지나야 한다. 첫 방문과 재방문의 분기를 어떻게 다룰지가 2단계 와이어프레임의 과제다. 저장소가 `localStorage`뿐이라 서버에서는 방문 이력을 알 수 없다는 제약이 여기에 걸린다.

홈의 대가 그리드 7개는 `/learn`의 그리드와 거의 같다. 어느 쪽으로 합치든 중복은 해소한다.

### 2. 듀오링고에서 가져오는 것과 가져오지 않는 것

| 가져옴 | 가져오지 않음 | 이유 |
|---|---|---|
| 경로를 홈으로 | 스트릭 | 조급함을 만드는 장치다 |
| 한 화면 한 과제 | 일일 목표 | 같음 |
| 진도 표시 | XP·리그 | 같음 |
| | 순서 잠금 | "관심 있는 장부터 골라 볼 수 있습니다"라는 약속을 철회해야 한다 |

루트 `CLAUDE.md`가 조급함을 유발하는 UI를 금지하고 "이 변경이 사용자를 '살까 말까'로 데려가는가"를 판단 기준으로 놓는다. 투자 학습에서 연속 학습일 카운터는 정확히 그 압박을 만든다. **경로와 진도까지만 가져온다.**

`dueJournalEntries`(90일 되돌아보기)는 그대로 둔다. 느림을 보상하는 장치이고 스트릭의 정반대다. 이 제품 고유의 것이므로 개편 후에도 중심에 놓는다.

### 3. 스크리너를 경로에서 떼어낸다

초안은 경로 ⑥번 노드에 스크리너를 두었다. 그러면 점수가 없는 세 명의 경로가 막다른 길이 된다. ⑥번을 자가진단·타 철학 연결·기록 종결 중 무엇으로 채울지 검토했으나, **⑥번 자체를 없애는 쪽을 택했다.**

- 일곱 경로가 전부 ⑤에서 같은 모양으로 끝난다. 7 대 4 비대칭이 화면에 드러나지 않는다
- 스크리너에 철학이 4개뿐인 것이 자연스러워진다. 경로의 결말이 아니라 도구의 옵션이기 때문이다
- 순위표는 반복해서 쓰는 도구인데 경로 종착점에 두면 한 번 쓰고 끝나는 자리가 된다

**대신 학습과 적용의 연결이 약해진다.** 이것은 개편 착수 이유 중 하나였으므로 링크로 유지한다. 노드로 승격하지 않는다. 양방향 모두 이미 코드에 있다.

- 마지막 챕터의 다음 카드 → 종목 찾기 (`app/learn/masters/[slug]/[chapter]/page.tsx:98`)
- 스크리너 상단 → 이 철학 배우러 가기 (`app/screener/[style]/page.tsx:55`)

점수 모델이 없는 세 명은 챕터 ⑤ 끝에 이 링크가 없다.

### 4. 스크리너를 한 페이지로 합치고 검색을 붙인다

`/screener/[style]` 4개를 `/screener` 하나로 합치고, 철학은 탭으로 전환한다. `screener-style-tabs`가 이미 렌더되고 있어 탭 UI는 있다.

상단에 종목명·티커 검색을 둔다. 검색 결과는 `/stocks/[ticker]`로 보낸다.

**철학 지정은 `?style=buffett` 쿼리로 받는다.** 챕터 ⑤ 끝의 안내 링크가 특정 철학으로 꽂혀야 하기 때문이다. `app/stocks/[ticker]/page.tsx`가 이미 `searchParams.style`을 같은 방식으로 쓴다.

한 페이지에 두 목적(발견과 확인)이 겹치는 것은 인지하고 진행한다. 순위표는 몰랐던 종목을 만나는 자리이고 검색은 아는 종목을 확인하는 자리다. 2단계 와이어프레임에서 두 영역의 시각적 분리를 다룬다.

정적 생성 페이지가 4개 줄어 약 427개가 된다.

### 4-1. 네비게이션에 없는 두 화면

`/learn/compare`(일곱 철학 횡단 비교)와 `/learn/scoring`(점수를 만드는 법)은 네비게이션에 없고 `/learn` 안의 보조 버튼으로만 닿는다. 둘 다 내용이 무겁다 — 비교는 7×5 매트릭스에 기록형 문항까지 있고, 점수 설명은 5단계에 커버리지 표를 낀다.

**두 화면을 없애지 않는다.** 다만 경로 중심 구조에서 어디에 놓을지는 2단계에서 정한다. 비교는 경로를 여러 개 지난 뒤에 의미가 생기고, 점수 설명은 스크리너에서 필요해지므로 진입 지점이 서로 다르다.

### 5. 종목 상세는 그대로 둔다

"종목을 열면 대가별 점수를 본다"는 요구는 **이미 구현돼 있다.** `components/StockLenses.tsx:94-111`이 `Object.keys(company.scores)`를 돌며 철학별 버튼을 만들고, 누르면 그 철학의 기준 막대와 판정 내역으로 전환한다. 학습노트 탭에도 철학별 적합도 목록이 있다.

세 렌즈(기업·차트·학습노트) 구조와 "두 관점을 합친 매수 점수를 만들지 않는다"는 원칙을 유지한다.

## 기술 제약

### 클라이언트로 내려도 되는 데이터의 상한

`lib/scores.ts`는 서버 전용이고 브라우저에서 평가되면 예외를 던진다(`scores.ts:27`). 실측한 크기는 다음과 같다.

| 데이터 | 크기 | 판단 |
|---|---|---|
| 티커 + 종목명 380개 | 10.8 KB | 검색에 쓴다. `companyNames()` 재사용 |
| 위 + 철학별 점수 | 61.7 KB | 필요하면 가능 |
| 기준별 판정 내역(criteria) 포함 | 2,243 KB | **클라이언트 금지** |

검색은 첫 번째 줄만 있으면 된다. `app/me/page.tsx`가 이미 `companyNames()`를 props로 내려보내는 패턴을 쓰므로 그대로 따른다.

380개 행을 한 번에 렌더하지 않는다. 검색 결과 또는 상위 N개만 그린다.

### 변경하지 않는 것

- **`CriteriaBar`** — 루트 `CLAUDE.md`가 이 제품의 정체성으로 지정했다. 점수 숫자를 키우거나 기준 막대를 빼는 방향의 변경은 하지 않는다
- **색** — 빨강·초록 금지. `--plum`(충족) / `--ochre`(미충족)만 쓰고 색만으로 의미를 전달하지 않는다
- **문구 규칙** — 권유형 문장을 쓰지 않는다. "현재" 대신 날짜를 쓴다
- **`lib/store.ts` 시그니처** — 전부 `Promise`를 돌려주는 상태를 유지한다. Supabase 교체 지점이다

## 미결 항목

### 차트 5단원을 제품에 넣을지

**이 문서에서 결정하지 않는다.** 루트 `CLAUDE.md`가 이 제품을 "기업을 고르는 법과 가격을 관찰하는 법을 함께 가르치는" 서비스로 정의하고, 원칙 3번이 정적 차트 교육을 정식 기능으로 지정한다. 빼는 결정은 제품 정의를 바꾸므로 별도 판단이 필요하다.

와이어프레임에서는 **경로 밖 보조 트랙으로 그리되 보류 표시를 단다.**

빼기로 할 경우 함께 정리해야 하는 것:

- `ChartAnalyzer` — 사용처 3곳 (`/practice`, `/learn/chart/[slug]`, `StockLenses` 차트 탭)
- `services/chart-api/app/services/prompt.py`의 `LESSON_IDS` ↔ `content/chartLessons.ts`의 `id` — 짝으로 묶여 있어 한쪽만 고치면 분석 결과가 없는 페이지로 링크된다
- 종목 상세의 세 렌즈 중 차트 관점 탭

## 2단계에서 그릴 화면

| 화면 | 주 내용 | 함께 정할 것 |
|---|---|---|
| 루트 | 첫 방문 소개와 재방문 경로의 분기 | 1번 결정의 미정 부분 |
| 경로 | 대가 7명 선택 → 5단계 노드 배치, 진도 표시 | 7명을 한 화면에 두는지, 고른 뒤 펼치는지 |
| 챕터 | 본문 + 연습문제 | 정보 밀도를 낮추는 것이 주 과제 |
| 종목 찾기 | 검색 · 철학 탭 · 순위표 · 정보 부족/판정 제외 목록 | 발견과 확인 두 영역의 분리 |
| 종목 상세 | 세 렌즈. 기존 구조 유지, 배치만 재검토 | 차트 탭은 미결 항목에 걸림 |
| 내 기록 | 경로 진도 · 관심종목 · 학습노트 · 90일 되돌아보기 | 지금 한 페이지에 다 쌓여 있음 |
| 비교 · 점수 설명 | 기존 내용 유지 | 진입 지점 (4-1 참고) |

## 확인 방법

이 문서는 구조 결정만 담으므로 코드 변경이 없다. 2단계 와이어프레임 착수 전에 다음을 확인한다.

- 위 결정이 `apps/web/CLAUDE.md`의 서버 전용 경계·디자인 토큰 규칙과 어긋나지 않는가
- 네비게이션에서 빠지는 화면이 생기면 진입 경로가 남아 있는가
- 경로 화면이 `lib/scores.ts`를 클라이언트에서 참조하지 않는가

# 2단계 — 와이어프레임 결정

여기서부터는 화면 내부 배치다. 목업은 `.superpowers/brainstorm/` 아래에 남아 있다(gitignore됨).

## 경로 화면

**목록은 카드 그리드, 경로는 세로 노드.**

- `/learn` — 대가 7명 카드. 카드마다 5칸 진도 막대와 "점수 모델 있음 / 자가진단" 구분. 상단에 "전체 35장 중 N장"
- `/learn/masters/[slug]` — 원형 노드 5개를 세로로. 한 대가당 5개뿐이라 스크롤이 짧다

노드 상태는 셋이다. 완료(채움) · 지금(굵은 테두리, 크게) · 미완(얇은 테두리). 색만으로 구분하지 않는다.

**미완 노드도 눌린다.** 흐림은 "아직 안 봤다"는 표시이지 잠금이 아니다. 듀오링고와 여기서 갈라진다.

종목 링크는 원형 노드가 아니라 사각 박스로 그려 경로의 단계가 아님을 모양으로 드러낸다.

일곱을 한 화면에 세로로 잇는 안(듀오링고 원형)은 버렸다. 35개 노드는 스크롤이 감당되지 않고, 무엇보다 **일곱 철학에 순서가 있다는 인상**을 준다. 이 제품에서 일곱은 병렬이고 `/learn/compare`가 이미 "어느 철학이 더 낫다는 표가 아니다"라고 명시한다.

## 챕터 화면

### 문제는 분량이 아니라 리듬이었다

화면별 한국어 텍스트를 실측한 결과다.

| 화면 | 글자 수 |
|---|---|
| `/learn/scoring` | 1,300 |
| `/screener/[style]` | 784 |
| `StockLenses` | 782 |
| 홈 | 670 |
| **챕터** | **22** |

챕터 페이지의 고정 텍스트는 22자이고 본문도 2문단 약 150자다. **"정보가 너무 많다"의 실제 대상은 점수 설명·스크리너·종목 상세·홈이다.**

챕터가 무겁게 느껴지는 원인은 `ChapterExercises`가 성격이 다른 문항 3개를 카드 3장으로 **동시에** 펼치기 때문이다. 게다가 `next.every(Boolean)` 조건이라 셋을 다 끝내야 `markLessonDone`이 걸리는데 그 조건이 화면에 드러나지 않는다.

### 4스텝으로 나눈다

| 스텝 | 내용 | 넘어가는 조건 |
|---|---|---|
| 1 읽기 | 제목 · 한 줄 요지 · 본문 2문단 | 조건 없음 |
| 2 확인 | 채점형 1문항, 즉시 정오와 해설 | 답을 고르고 확인 |
| 3 적용 | 써보기 **또는** 기록 — 둘 중 하나만 | 한 글자라도 쓰면 |
| 4 정리 | 이 장의 한 문장 + 다음 장 | — |

한 장에 3~5분. 4스텝이 끝나면 장이 끝나는 것이 화면에 드러나므로 진도 시점도 명확해진다.

4의 닫는 문장은 `chapter.lede`를 재사용한다. 새로 쓸 글이 없다.

### 문항 배치를 고르게 맞춘다

지금 분포는 장마다 다르다 — 버핏 1장 3개, 린치 3장 4개, 나머지 대부분 2개. 총 80문항(채점 26 · 써보기 24 · 기록 30).

**채점 1 + (써보기 또는 기록) 1**로 고정한다. 총량은 약 70문항으로 준다.

### 기록형을 30개에서 7개로 줄인다

`dueJournalEntries()`는 90일 지난 기록을 전부 돌려준다. 기록형이 30개면 커리큘럼을 마친 사용자에게 90일 뒤 30개가 한꺼번에 돌아온다. **되돌아보기는 이 제품에서 가장 고유한 장치인데 그 양이면 장치가 죽는다.**

기록은 철학마다 5장 끝에 하나씩만 둔다. 일곱을 다 지나도 7개다. 빠지는 23개는 써보기로 바꾼다. 써보기는 즉시 체크포인트가 나와 그 자리에서 닫히고 쌓이지 않는다.

## 커리큘럼과 점수 모델은 서로 다른 두 체계다

**이번 검토에서 가장 중요한 확인이다.** 버핏 챕터 본문을 실제로 읽어 대조한 결과다.

| 장 | 가르치는 것 | 대응하는 기준 |
|---|---|---|
| 1 전제 | 능력범위 | 없음 |
| 2 탐색 | 해자 5형태(전환비용·네트워크·규모·무형자산·원가우위) | ROIC가 본문에 없음 |
| 3 검증 | 소유주이익 = 순이익 + 비현금비용 − 유지 자본지출 | `BUF_FCF_MARGIN`과 **다른 지표** |
| 4 처분 | 미실현이익과 세금, 복리 | 부채·이자와 무관 |
| 5 실패 | 프리시전 캐스트파츠 · 자본 구조 | EV/EBIT이 본문에 없음 |

챕터는 사고방식을 가르치고, 8개 기준은 공시 데이터로 판정 가능한 지표다. 둘 사이에 다리가 없다.

**이 분리는 의도된 것으로 보인다.** 2026-08-06 커리큘럼 스펙에 이런 문장이 있다 — "재무 지표로 근사하면 그 스타일이 실제로 묻는 것과 다른 것을 재게 되고, 이는 스타일을 잘못 가르치는 결과다."

### 따라서 기준 소개는 5장 끝 한 곳에만 둔다

장마다 "이 개념이 왜 이 지표가 되는가"를 붙이려면 철학당 8개 × 4철학 ≈ 30개 설명 문장을 새로 써야 한다. 대신 **경로 끝에 한 블록**으로 모은다.

- "배운 사고방식을 공시 숫자로 옮기면 이 8개가 됩니다"
- 실제 종목 하나로 종합 확인 — 종목·수치·판정은 `scores.json`에서 온다
- 그다음 380종목 목록으로

`CriteriaBar`는 여기서 한 번 등장한다. 장마다 칸이 하나씩 켜지는 방식은 장별 매핑이 성립하지 않으므로 채택하지 않는다.

**`/learn/scoring`(1,300자)이 이미 이 설명을 하고 있다.** 이 화면을 경로 끝의 기준 소개 자리로 접어 넣으면 갈 곳 없던 화면에 자리가 생기고 종합 확인에 내용이 생긴다. 4-1의 미정 항목이 여기서 해소된다.

## 경로 끝 — 4명과 3명

경로의 **모양은 같고 마지막 카드의 내용만 다르다.**

| | 마지막 |
|---|---|
| 버핏 · 그레이엄 · 린치 · 그린블랫 | 기록 → 기준 소개와 종합 확인 → 380종목 |
| 막스 · 피셔 · 소로스 | 기록 → "이 철학은 여기까지입니다" + 숫자로 옮기지 않는 이유 |

세 명에게 종합 확인이 없는 것은 결핍이 아니라 "이 철학은 공시 숫자로 옮기지 않는다"는 제품의 입장이다. 그 문장을 그대로 쓴다.
