# 챕터 핵심 블록과 각주 대상

## 목표

일곱 대가 35개 장이 모두 같은 무게의 문단 나열로만 조판돼, 한 장을 열었을 때 무엇이 핵심인지 보이지 않는다. 각 장에 그 장의 뼈대를 담는 블록을 하나씩 세워 시선이 멈추는 지점을 만든다. 함께, 본문 문단에 걸리지 않는 각주 10개를 제 대상에 붙인다.

## 문제

### 강조 지점이 없다

`Chapter.body`는 `string[]`이고 `ChapterExercises`의 읽기 스텝이 이를 `<p>`로만 펼친다. 강조를 표현할 수단이 데이터 모델에 없다. 제목과 리드 뒤로는 3~5문단이 균질하게 이어진다.

여러 장이 이미 "확인 항목은 넷이다", "매도 사유는 정확히 셋이다", "조절 수단은 셋이다", "순유동자산 = 유동자산 − 총부채" 같은 뼈대를 갖고 있으면서 그것을 산문 안에 묻어 두고 있다.

### 각주가 본문과 무관한 자리에 있다

`SourceNote.paragraph`를 생략하면 장 전체 각주가 되고, 읽기 스텝의 출처 목록에 대상 표시 없이 섞인다. 전체 114개 각주 중 10개가 여기 해당하는데 성격이 셋으로 갈린다.

| 성격 | 개수 | 예 |
|---|---|---|
| 문항에만 걸리는 것 | 2 | graham 2장·lynch 3장의 "확인 문항의 숫자는 계산 연습을 위해 만든 것이다" |
| 매도 유형 이름 | 6 | graham·fisher·greenblatt·lynch·marks·soros 4장의 "매도 유형 이름 'X형'은 이 과정이 붙인 것이다" |
| 진짜 장 전체 단서 | 2 | greenblatt 2장 스크리너 제외 조건, marks 4장 "한계 주의" |

앞의 8개는 본문을 읽는 자리에 나올 이유가 없다. graham 2장의 창작 각주는 본문에 존재하지 않는 숫자를 설명한다.

## 범위

### 하는 것

- `Chapter`에 `highlight` 필드를 신설하고 35개 장에 하나씩 채운다.
- `SourceNote`에 `on` 필드를 더해 문항·매도 유형을 각주 대상으로 지정할 수 있게 한다.
- 읽기 스텝에 강조 블록을 렌더링하고, 출처 목록에 대상 표시를 붙인다.
- `validate.ts`에 새 규칙을 넣고 `validate.test.ts`에 케이스를 추가한다.
- 각주가 인용한 본문 구절이 실제로 남아 있는지 보는 검사를 저장소 테스트로 추가한다.

### 하지 않는 것

- **본문 문자열을 고치지 않는다.** `body` 배열도, 그 안의 문장도 그대로 둔다.
- 각주 114개의 기존 `paragraph` 값을 건드리지 않는다.
- 대가별 시각 정체성은 다루지 않는다. 이번 문제는 장 안의 위계다.
- `Graded`·`Guided`·`Journal` 컴포넌트는 손대지 않는다.
- 문항 각주를 문항 화면에 함께 띄우는 일은 후속으로 미룬다.

## 데이터 모델

### 핵심 블록

```ts
/** 그 장의 뼈대. 본문 위에 한 번 세운다.
 *  body와 별개 필드이므로 각주의 paragraph 인덱스에 영향을 주지 않는다. */
export type Highlight =
  | { kind: "formula"; label: string; expr: string; caveat?: string }
  | { kind: "list"; label: string; items: string[]; ordered?: boolean; caveat?: string }
  | { kind: "point"; label: string; text: string };

export type Chapter = {
  title: string;
  lede: string;
  highlight: Highlight;
  body: string[];
  sources: SourceNote[];
  exercises: Exercise[];
};
```

`highlight`는 **필수**다. "35개 장 전부 하나씩"이 결정사항이므로 타입이 강제한다. `BANNED_PHRASES`와 기준 개수 테스트가 그렇듯, 이 저장소는 원칙을 코드로 막는다. 대가로, 35개를 다 채우기 전에는 타입 검사가 통과하지 않는다.

`ordered`는 순서가 뜻을 갖는 열거에만 붙인다. soros 2장의 붐-버스트 5단계와 3장의 "가설 → 진입 → 검증 → 확대"는 순서가 정보이고, graham 3장의 확인 항목 넷은 순서가 없다. 번호를 일괄로 매기면 없는 순서를 있다고 말하게 된다.

### 각주 대상

```ts
export type SourceNote = {
  kind: SourceKind;
  /** 몇 번째 본문 문단(0부터)에 붙는 각주인가. */
  paragraph?: number;
  /** 문단이 아닌 대상에 붙는 각주. paragraph와 함께 쓰지 않는다.
   *  둘 다 없으면 지금처럼 장 전체에 붙는다. */
  on?: { exercise: number } | { sellType: true };
  text: string;
};
```

기존 필드를 유지하고 더하기만 한다. 각주 114개 중 104개는 한 글자도 바뀌지 않고, 8개만 `on`을 얻고, 2개는 지금처럼 장 전체로 남는다.

유니온 하나로 통일하는 쪽(`target: {on:'paragraph',index} | …`)이 타입은 더 정직하지만 114개를 전부 고쳐야 한다. 문단 인덱스는 이 저장소에서 가장 깨지기 쉬운 지점이므로 건드리는 양을 줄이는 쪽을 택한다. 대신 `paragraph`와 `on`이 동시에 지정되는 조합은 타입이 못 막으므로 `validate.ts`가 검사한다.

## 35개 장 배정

본문에 이미 있는 재료를 기준으로 형태를 나눈 결과다. 빈 장은 없다.

| 형태 | 개수 | 예 |
|---|---|---|
| `formula` | 7 | graham 2장 NCAV · buffett 3장 소유주이익 · lynch 3장 PEG · lynch 5장 이익×배수 · greenblatt 2장 합산 순위 |
| `list` | 18 | graham 3장 확인 항목 넷 · fisher 4장 매도 사유 셋 · lynch 2장 여섯 유형 · marks 4장 조절 수단 셋 · soros 2장 5단계 |
| `point` | 10 | buffett 1장 경계의 선명함 · marks 3장 위험은 영구 손실 · soros 4장 비대칭 |

블록 문안은 본문에 이미 있는 내용에서 뽑는다. 압축과 발췌는 하되 본문에 없는 주장을 새로 넣지 않는다. 옮길 것이 없는 장이 나오면 임의로 문안을 만들지 말고 그 장의 본문 구조부터 다시 본다.

바로 아래 문단과 글자 그대로 겹치지 않게 한다. 같은 문장이 블록과 첫 문단에 연달아 나오면 강조가 아니라 중복으로 읽힌다. graham 2장이 그 예로, 블록은 `순유동자산 = 유동자산 − 총부채`만 세우고 정의는 본문이 계속 맡는다.

## 렌더링

### 컴포넌트 경계

`ChapterExercises.tsx`는 443줄에 스테퍼 상태·문항 3종·출처를 함께 담고 있다. 이번에 손대는 둘만 파일로 꺼낸다.

```
components/chapter/ChapterHighlight.tsx   신설. 순수 표시용
components/chapter/ChapterSources.tsx     기존 Sources 이동 + 대상 표시
```

둘 다 직렬화 가능한 props만 받고 훅을 쓰지 않는다. `lib/scores.ts`를 import하지 않는다.

### 읽기 스텝

순서는 **강조 블록 → 본문 → 출처**다. 블록이 이정표로 먼저 서고 아래 문단이 그것을 풀어낸다.

블록은 챕터 페이지의 읽기 스텝에만 나온다. 대가 개요(`/learn/masters/[slug]`)와 비교 페이지에는 넣지 않는다. `ChapterExercises`의 `highlight` prop을 선택으로 두는 이유도 이것이다 — `/learn/compare`는 본문 한 문단만 넘기고 강조가 없다.

### 출처 목록

대상별로 묶고 배지를 붙인다.

| 대상 | 배지 |
|---|---|
| `paragraph: n` | `n+1문단` (지금과 같음) |
| `on: { exercise: n }` | `n+1번 문항` |
| `on: { sellType: true }` | `매도 유형` |
| 둘 다 없음 | `이 장 전체` |

지금은 대상이 없으면 배지가 아예 없어서 본문 각주와 구분되지 않는다. 넷 다 배지를 갖게 해 대상 없는 각주를 없앤다. 펼치지 않아도 원전·정리·창작 비율이 보이는 현재 요약줄은 유지한다.

## 스타일

`globals.css`에 `.highlight` 계열을 추가한다. 골드 계열을 쓴다.

- 리드가 이미 `--wine` 좌측 보더를 쓰므로 강조까지 와인이면 둘이 경합한다.
- 골드는 학습 화면에서 가격 방향을 뜻하지 않으므로 색 규칙에 어긋나지 않는다.
- 색만으로 말하지 않는다. 위쪽 3px 실선과 1px 테두리라는 형태가 먼저 구분한다.
- 라벨은 `--gold-deep` 대문자, 수식은 `font-variant-numeric: tabular-nums`.
- `ordered: true`일 때만 번호 상자를 붙인다. 아니면 표식 없이 나열한다.
- 하드코딩한 hex를 새로 넣지 않는다.

## 검증

### validate.ts에 넣을 규칙

| 규칙 | 왜 |
|---|---|
| `highlight`의 `label`·`text`·`expr` 공백 검사 | 빈 블록이 조용히 렌더링되는 것을 막는다 |
| `list.items`가 비면 잡는다 | 위와 같다 |
| `paragraph`와 `on` 동시 지정 금지 | 두 옵션 필드의 배타성을 타입이 못 잡는다 |
| `on.exercise` 인덱스가 `exercises` 범위 밖이면 잡는다 | 범위 밖이면 없는 문항을 가리킨다 |
| 금지어 검사 대상에 `highlight` 포함 | 지금 `title + lede + body`만 본다. 새 블록만 검사망을 빠져나간다 |

### 테스트

- `validate.test.ts`에 규칙당 케이스를 하나씩 추가한다.
- "실제 일곱 커리큘럼은 문제를 내지 않는다" 케이스가 새 규칙까지 함께 검사한다.
- 각주와 문항이 따옴표로 인용한 구절이 해당 장의 본문·리드·제목에 실제로 있는지 보는 검사를 새 테스트로 추가한다. 2026-08-13 기준 각주 쪽 11개, 문항 쪽 13개가 있고 전부 걸려 있다. 본문을 고칠 때 인용이 함께 깨지는 것을 막는 장치이며, 이번 변경 자체는 본문을 건드리지 않으므로 회귀 감시용이다.

### 접근성 및 확인

- 375px에서 블록이 넘치지 않고 캐비엇이 접힌다.
- 블록은 장식이 아니라 내용이므로 스크린리더가 본문 순서대로 읽는다. `aria-hidden`을 쓰지 않는다.
- 번호 상자는 CSS `counter`로 그리되 순서가 뜻을 갖는 경우에만 쓴다.
- 키보드 Tab으로 기존 조작이 그대로 동작한다. 블록은 포커스 대상을 새로 만들지 않는다.
- `cd apps/web && npm test`와 `npm run build`를 실행한다.
- 빌드 후 `grep -rl "evEbitMedian5y" .next/static/`이 비어 있다.

## 위험과 완화

| 위험 | 완화 |
|---|---|
| `highlight` 필수화로 35개를 채우기 전까지 빌드가 깨진다 | 타입 추가와 콘텐츠 채우기를 한 변경으로 묶는다. 중간 상태를 커밋하지 않는다 |
| 블록 문안을 지어내면서 원전에 없는 내용이 들어간다 | 본문 문장을 옮기는 것을 원칙으로 한다. 옮길 것이 없으면 본문부터 본다 |
| `on`과 `paragraph`가 함께 지정된 각주가 조용히 통과한다 | `validate.ts`가 잡고 테스트가 그 케이스를 갖는다 |
| 문항 각주가 여전히 읽기 화면에 남는다 | 이번에는 배지로 대상만 밝힌다. 문항 화면에 함께 띄우는 것은 후속 작업 |
