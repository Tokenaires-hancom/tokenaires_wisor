# /learn 일곱 철학 비교표를 고를 수 있게 만든다

작성 2026-08-16 · 영역 `apps/web` (1번)

## 왜

`/learn` 하단의 7×5 비교표는 지금 읽기만 하는 표다. 사용자가 이 표에 기대하는 것은
자신이 중요하게 여기는 기준을 골라 두고, 자신의 답이 어느 대가와 겹치는지 확인하는
것이다. 지금 표는 그 동작을 지원하지 않는다.

읽기만 하는 표로도 부족한 이유가 하나 더 있다. 칸이 장 제목이라 은유가 섞여 있다.
"우위는 일상에 있다", "심리 온도계를 읽는다"는 그 장을 이미 읽은 사람만 안다.
고르려면 칸만 보고 뜻이 서야 한다.

## 무엇을 바꾸지 않는가

- 겹침 수를 근거로 "당신은 버핏형입니다" 같은 단정을 하지 않는다. 관찰까지만 말한다.
- 선택을 저장하지 않는다. 새로고침하면 사라진다. `lib/store.ts`를 건드리지 않는다.
- 표에서 각 장·대가로 나가는 링크는 계속 없다. 여기는 고르는 자리다.
- 장 페이지의 `title`과 `lede`는 그대로 둔다.

---

## 1. 칸 내용 — 비교표 전용 한 줄

`Chapter`에 `oneLine: string`을 더한다. 표는 이 값만 쓴다.

작성 규칙:

- 한 문장, 공백 포함 **24자 이내**
- 서술형(`~한다`)으로 끝내고 종결 마침표를 붙이지 않는다
- 은유와 제목투를 쓰지 않는다 — "심리 온도계", "다이얼을 돌린다"는 실격
- 판단어와 권유형을 쓰지 않는다 (`BANNED` 검사가 이미 있다)

예:

| 지금 (`title`) | `oneLine` |
|---|---|
| 우위는 일상에 있다 | 일상에서 본 회사를 후보로 삼는다 |
| 심리 온도계를 읽는다 | 낙관인지 비관인지로 위치를 잰다 |
| 세 경우 말고는 떠나지 않는다 | 판단 오류·기업 변질·기회비용만 매도 사유다 |
| 회계이익이 아니라 주주 몫의 현금 | 회계이익 대신 주주에게 남는 현금을 센다 |

35개 문장 전문은 구현 전에 따로 확인받는다.

`validate.ts`의 `curriculumProblems`에 규칙을 더한다. 빌드에서 도는 검사라 건너뛸 수
없다.

- `oneLine`이 비어 있으면 실패
- `oneLine`이 24자를 넘으면 실패 (넘으면 표가 가로로 넘친다 — 2절과 묶인 제약이다)
- `oneLine`이 `.`로 끝나면 실패
- `oneLine`도 `BANNED` 검사 대상에 넣는다 (지금은 `title`·`lede`·`body`만 본다)

## 2. 표 크기 — 데스크톱에서 한눈에

지금 `.comparison-matrix`는 `min-width: 980px`이고 `.comparison-scroll`이
`overflow-x: auto`다. 칸이 길어져도 데스크톱에서 가로로 밀리지 않게 못을 박는다.

- `min-width: 980px`를 기본에서 뺀다. 표는 `.wrap` 폭(약 1032px)을 다 쓴다
- 대가 이름 열 `10rem → 8rem`
- 칸 패딩 `1rem → 0.75rem`
- `@media (max-width: 820px)`에서만 `min-width: 900px`를 되살린다. 모바일은 지금처럼
  가로 스크롤이다

내용 열 하나가 약 180px이 되고, 24자 문장이 두세 줄에 들어간다. 7행 전체가 약 600px로
한 화면에 담긴다.

하단 안내 `표는 좌우로 움직여 볼 수 있습니다.`는 데스크톱에서 거짓말이 되므로
820px 미만에서만 보이게 한다.

## 3. 선택 — 칸을 색으로 채운다

체크박스를 따로 그리지 않는다. 칸 자체가 선택 대상이다.

- `<td>` 안에 칸 크기를 채우는 `<button type="button" role="checkbox" aria-checked>`를
  둔다. 별도 입력 요소 없이 Tab 이동과 Space 선택이 된다
- 고른 칸: `--wine` 배경 + 흰 글씨. 안 고른 칸: `--surface` + `--ink-soft`
- 채움과 글자색이 함께 뒤집혀 명도만으로도 구분된다. 색에만 기대지 않는다는 규칙을
  이 대비가 만족시킨다
- 흰 글씨를 쓰지만 `--gold` 위가 아니라 `--wine` 위이므로 대비 제약(16px·700)은
  해당하지 않는다
- `--wine`은 `/learn` 화면의 방향과 무관한 표시라 규칙에 맞는다. `--gold`는 데이터
  화면의 충족 표시이므로 여기서 쓰지 않는다

35칸 전부 자유 다중 선택이다. 한 열에 여러 칸을 고를 수 있고 막지 않는다.

### 실패 열

실패 열 7칸은 "이 철학은 이렇게 무너진다"라서 다른 열과 성격이 다르다. 같은 질문으로
두면 "나는 이 실패를 선호한다"가 된다. 열 머리 질문만 바꾼다.

`CHAPTER_SLOTS`에 `picks` 필드를 더한다. 표는 `picks`를, 장 페이지는 지금처럼 `asks`를
쓴다.

| 열 | `asks` (장 페이지) | `picks` (표) |
|---|---|---|
| 전제 | 이 철학은 시장에 대해 무엇을 가정하는가 | 이 가정을 받아들이는가 |
| 탐색 | 무엇을, 어디서 찾는가 | 이렇게 찾는가 |
| 검증 | 사기 전에 무엇을 확인하는가 | 이것을 확인하는가 |
| 처분 | 언제까지 들고, 무엇이 팔게 하는가 | 이때 파는가 |
| 실패 | 이 철학은 어떻게 무너지는가 | **이 대가를 감수할 수 있는가** |

## 4. 결과 — 표 안에서만

- 대가 이름 칸에 겹친 수를 붙인다. 0인 대가는 숫자를 붙이지 않는다
- 표 위 요약 한 줄: `고른 12칸 · 버핏 5 · 린치 3 · 그레이엄 2 · 마크스 1 · 소로스 1`
  (0인 대가는 빼고, `CURRICULA` 순서를 유지한다. 동점을 순위로 가르지 않는다)
- 아무것도 안 골랐을 때: `칸을 고르면 어느 철학과 겹치는지 여기에 나옵니다`
- 초기화 버튼 하나. 고른 칸이 있을 때만 보인다
- `당신은 버핏형입니다`, `버핏이 가장 잘 맞습니다` 같은 문장을 쓰지 않는다.
  `고른 12칸 중 5칸이 버핏과 겹칩니다`까지다

```
      자신에게 맞는 답을 골라 보세요. 어느 철학이 더 낫다는
      표가 아니라, 자신의 답이 누구와 몇 칸 겹치는지 보는
      표입니다.
```

## 6. 구조

`StyleComparisonTable.tsx`는 서버 컴포넌트로 남긴다. 여기에 `"use client"`를 붙이면
`content/curriculum`의 본문 전체와 `content/masters.ts`(472줄)가 브라우저 번들에
실린다.

```
StyleComparisonTable.tsx   서버. 머리글을 그리고, 아래 props만 뽑아 내려보낸다
  └─ StyleComparisonPicker.tsx   "use client". 선택 상태와 표를 담당한다
```

`Picker`가 받는 props는 이것뿐이다. 커리큘럼 본문도 대가 객체도 넘기지 않는다.

```ts
type PickerSlot = { no: number; label: string; picks: string };
type PickerRow = { masterId: string; name: string; cells: string[] };  // cells.length === 5
```

상태는 `Set<string>`("`${masterId}-${no}`") 하나다.
