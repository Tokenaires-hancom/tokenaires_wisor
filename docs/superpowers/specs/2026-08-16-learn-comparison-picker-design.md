# /learn 일곱 철학 비교표를 고를 수 있게 만든다

작성 2026-08-16 · 영역 `apps/web` (1번)

## 왜

`/learn` 하단의 7×5 비교표는 지금 읽기만 하는 표다. 사용자가 이 표에 기대하는 것은
자신이 중요하게 여기는 기준을 골라 두고, 자신의 답이 어느 대가와 겹치는지 확인하는
것이다. 지금 표는 그 동작을 지원하지 않는다.

읽기만 하는 표로도 부족한 이유가 하나 더 있다. 칸이 장 제목이라 은유가 섞여 있다.
"우위는 일상에 있다", "심리 온도계를 읽는다"는 그 장을 이미 읽은 사람만 안다.
고르려면 칸만 보고 뜻이 서야 한다.

## 무엇을 바꾸지 않는가

- 겹침 수를 근거로 "당신은 버핏형입니다" 같은 단정을 하지 않는다. 관찰까지만 말한다.
- 선택을 저장하지 않는다. 새로고침하면 사라진다. `lib/store.ts`를 건드리지 않는다.
- 표에서 각 장·대가로 나가는 링크는 계속 없다. 여기는 고르는 자리다.
- 장 페이지의 `title`과 `lede`는 그대로 둔다.

---

## 1. 칸 내용 — 비교표 전용 한 줄

`Chapter`에 `oneLine?: string`을 더한다. 표는 이 값만 쓴다. 비교표에 나가는 칸에만
두므로 선택 항목이고, 짝이 맞는지는 `validate.ts`가 본다.

작성 규칙:

- 한 문장, 공백 포함 **24자 이내**
- 서술형(`~한다`)으로 끝내고 종결 마침표를 붙이지 않는다
- 은유와 제목투를 쓰지 않는다 — "심리 온도계", "다이얼을 돌린다"는 실격
- 판단어와 권유형을 쓰지 않는다 (`BANNED` 검사가 이미 있다)

예:

| 지금 (`title`) | `oneLine` |
|---|---|
| 우위는 일상에 있다 | 일상에서 본 회사를 후보로 삼는다 |
| 심리 온도계를 읽는다 | 시장이 낙관인지 비관인지 조건을 본다 |
| 세 경우 말고는 떠나지 않는다 | 판단 오류·기업 변질·기회비용에만 판다 |
| 회계이익이 아니라 주주 몫의 현금 | 회계이익 대신 주주 몫 현금을 센다 |

문장은 28개다. 아래 3절에서 실패 열을 뺐기 때문이다.

`validate.ts`의 `curriculumProblems`에 규칙을 더한다. 빌드에서 도는 검사라 건너뛸 수
없다.

- `picks`가 있는 칸인데 `oneLine`이 없으면 실패
- `picks`가 없는 칸(실패)인데 `oneLine`이 있으면 실패 — 아무 데도 안 쓰이는 문장이 남는다
- `oneLine`이 비어 있으면 실패
- `oneLine`이 24자를 넘으면 실패 (넘으면 칸이 세 줄을 넘겨 표가 한 화면을 벗어난다)
- `oneLine`이 `.`로 끝나면 실패
- `oneLine`도 `BANNED` 검사 대상에 넣는다 (지금은 `title`·`lede`·`body`만 본다)

## 2. 표 크기 — 데스크톱에서 한눈에

지금 `.comparison-matrix`는 `min-width: 980px`이고 `.comparison-scroll`이
`overflow-x: auto`다. 칸이 길어져도 데스크톱에서 가로로 밀리지 않게 못을 박는다.

- `min-width: 980px`를 기본에서 뺀다. 표는 `.wrap` 폭(약 1032px)을 다 쓴다
- 대가 이름 열 `10rem → 8rem`
- 칸 패딩 `1rem → 0.75rem`
- `@media (max-width: 820px)`에서만 `min-width: 900px`를 되살린다. 모바일은 지금처럼
  가로 스크롤이다

열이 넷이라 내용 열 하나가 약 210px이 되고, 24자 문장이 두 줄에 들어간다. 7행 전체가
약 550px로 한 화면에 담긴다.

하단 안내 `표는 좌우로 움직여 볼 수 있습니다.`는 데스크톱에서 거짓말이 되므로
820px 미만에서만 보이게 한다.

## 3. 선택 — 칸을 색으로 채운다

체크박스를 따로 그리지 않는다. 칸 자체가 선택 대상이다.

- `<td>` 안에 칸 크기를 채우는 `<button type="button" role="checkbox" aria-checked>`를
  둔다. 별도 입력 요소 없이 Tab 이동과 Space 선택이 된다
- 고른 칸: `--wine` 배경 + 흰 글씨. 안 고른 칸: `--surface` + `--ink-soft`
- 채움과 글자색이 함께 뒤집혀 명도만으로도 구분된다. 색에만 기대지 않는다는 규칙을
  이 대비가 만족시킨다
- 흰 글씨를 쓰지만 `--gold` 위가 아니라 `--wine` 위이므로 대비 제약(16px·700)은
  해당하지 않는다
- `--wine`은 `/learn` 화면의 방향과 무관한 표시라 규칙에 맞는다. `--gold`는 데이터
  화면의 충족 표시이므로 여기서 쓰지 않는다

28칸 전부 자유 다중 선택이다. 한 열에 여러 칸을 고를 수 있고 막지 않는다.

### 실패 열은 표에서 뺀다

실패 칸은 "이 철학이 무너지는 이유"라서 "나는 이렇게 한다"로 고를 수 있는 대상이
아니다. 표에서 뺀다. 배우는 장으로는 그대로 남는다 — 커리큘럼은 다섯 장 그대로다.

`CHAPTER_SLOTS`에 `picks`를 선택 항목으로 더하고 실패 칸에서는 뺀다. 그러면 "`picks`가
있는 칸만 비교표에 나온다"가 코드로 드러난다. 장 페이지는 지금처럼 `asks`를 쓴다.

| 열 | `asks` (장 페이지) | `picks` (표) |
|---|---|---|
| 전제 | 이 철학은 시장에 대해 무엇을 가정하는가 | 시장을 어떻게 보는가 |
| 탐색 | 무엇을, 어디서 찾는가 | 살 회사를 어떻게 찾는가 |
| 검증 | 사기 전에 무엇을 확인하는가 | 살 회사의 무엇을 확인하는가 |
| 처분 | 언제까지 들고, 무엇이 팔게 하는가 | 가진 주식을 언제 파는가 |
| 실패 | 이 철학은 어떻게 무너지는가 | *(없음 — 표에 나오지 않는다)* |

열 머리의 `01`~`04` 번호는 두지 않는다. 넷뿐이라 순서를 셀 이유가 없다.

## 4. 결과 — 표 안에서만

- 대가 이름 칸에 겹친 수를 붙인다. 0인 대가는 숫자를 붙이지 않는다
- 표 위 요약 한 줄: `12칸을 골랐습니다. 워런 버핏 42% 피터 린치 25% …`
  (0인 대가는 빼고, `CURRICULA` 순서를 유지한다. 동점을 순위로 가르지 않는다)
- 비율은 최대잉여법(`lib/percent.ts`)으로 합이 항상 100이 되게 맞춘다
- 아무것도 안 골랐을 때: `칸을 고르면 어느 철학과 몇 퍼센트 겹치는지 여기에 나옵니다`
- 초기화 버튼 하나. 고른 칸이 있을 때만 보인다
- `당신은 버핏형입니다`, `버핏이 가장 잘 맞습니다` 같은 문장을 쓰지 않는다.
  `워런 버핏 42%`까지다

## 6. 구조

`StyleComparisonTable.tsx`는 서버 컴포넌트로 남긴다. 여기에 `"use client"`를 붙이면
`content/curriculum`의 본문 전체와 `content/masters.ts`(472줄)가 브라우저 번들에
실린다.

```
StyleComparisonTable.tsx   서버. 머리글을 그리고, 아래 props만 뽑아 내려보낸다
  └─ StyleComparisonPicker.tsx   "use client". 선택 상태와 표를 담당한다
```

`Picker`가 받는 props는 이것뿐이다. 커리큘럼 본문도 대가 객체도 넘기지 않는다.

```ts
type PickerSlot = { no: number; label: string; picks: string };
type PickerRow = { masterId: string; name: string; cells: string[] };  // cells.length === 4
```

상태는 `Set<string>`("`${masterId}-${no}`") 하나다.

- `npm run build` 통과. 정적 페이지 수가 435개에서 줄지 않는다
- `grep -rl "evEbitMedian5y" .next/static/` 가 비어 있다
- `.next/static/`에서 커리큘럼 본문 한 구절(예: `확증 편향이란`)이 잡히지 않는다 —
  서버/클라이언트 경계가 실제로 지켜졌는지 보는 검사다. 대가 소개 문장은 `masters.ts`에
  있고 `MobileMasterDock`이 클라이언트에서 쓰므로 검사어로 쓰면 안 된다
- 테스트 통과. `validate.test.ts`에 `oneLine` 규칙 실패 사례를 더한다.
  이 저장소의 `npm test`는 Node 22+가 필요하다(글롭·TS 스트리핑) — Node 20에서는
  `npx tsx --test content/*.test.ts content/curriculum/*.test.ts lib/*.test.ts`로 돌린다
- 1280px에서 표에 가로 스크롤이 없다. 375px에서 가로 스크롤로 다 볼 수 있다
- Tab만으로 28칸을 모두 오가고 Space로 선택·해제된다

## 구현하며 바뀐 것

위 설계를 만들고 나서 화면을 보며 정한 것들이다. 설계와 어긋나는 부분은 아래가 맞다.

**결과를 레일의 그래프로 옮겼다.** 대가 이름 밑에 실시간 퍼센트를 붙이니 칸을 누를
때마다 행 높이가 바뀌어 표 전체가 흔들렸다. 표 오른쪽 14rem 레일에 가로 막대 그래프를
두고, `클릭하여 내 기준 살펴보기`를 눌러야 열리게 했다. 레일 폭은 늘 잡혀 있어 그래프가
열려도 표가 다시 흐르지 않는다.

**대가마다 색을 준다.** `public/investors/*.png` 초상의 대표색에서 출발했다. 그대로 쓰면
버핏·그린블랫과 그레이엄·소로스가 사실상 같은 색이라 dataviz 검증기에서 떨어진다. 색상
계열은 두고 명도로 벌려 `--master-*` 일곱 개를 만들었다(전체 쌍 검증 통과, 색각이상 최소
ΔE 7.2 — 6–8 대역이라 얼굴·이름·퍼센트를 함께 붙이는 것이 조건이다). 칸을 채울 때는 흰
글씨 4.5:1을 맞춘 `--master-*-deep`을 쓴다.

**얼굴을 넣는다.** 표의 이름 칸과 그래프 항목에 초상을 두고, 둘레 고리를 그 대가의
색으로 칠해 표와 그래프를 잇는다.

**표를 `.wrap` 밖으로 넓혔다.** 최대 1280px. 레일을 빼고도 표가 레일 이전보다 넓다.

**좁은 화면(820px 미만)은 표를 버리고 질문 단위로 쌓는다.** 행이 대가고 열이 질문이라
CSS로는 전치되지 않아 마크업이 한 벌 더 있다. `display: none`이라 접근성 트리에서는
한 벌만 읽힌다. 질문은 접었다 펼 수 있고 접어도 고른 개수가 배지로 남는다.
**여기에는 대가 이름을 넣지 않는다** — 이름을 보고 고르면 그래프가 확인이 아니라 답
맞히기가 된다.

**대가 카드 그리드에서 비교표로 가는 링크를 놓았다.** 리본 화살표 꼭지 바로 아래
9px 지점에 두 줄로 선다. 좌표는 `globals.css`의 `--arrow-x`/`--arrow-y`이고
`MasterGrid.tsx`의 화살표 path와 짝이다. **한쪽만 고치면 조용히 어긋난다.**

## 남은 것

- `.compare-jump`의 `--gold-deep`은 흰 배경에서 3.37:1이다. 0.85rem 본문 크기 기준
  4.5:1에 못 미친다. 위치와 문구 길이를 화면마다 고정하는 쪽을 택한 결과다.
- 그래프에 빨강 계열 둘과 초록 계열 하나가 함께 나온다. 빨강·초록 금지는 주식 화면
  규칙이고 여기는 `/learn`이라 위반은 아니지만, 손익으로 읽힐 소지는 남는다.
- 35개 중 실패 칸 일곱은 `oneLine`이 없다. 비교표에 나가지 않기 때문이다.
