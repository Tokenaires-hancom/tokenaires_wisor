# 유저 시나리오 — Wisor

> 기준 시점 2026-08-18 · 저장소 실제 코드(`a41fb3b` + 미커밋 작업 트리)에서 확인한 흐름입니다.
> 아래 발견 중 일부는 아직 커밋되지 않은 변경에 걸려 있어, `a41fb3b`만 체크아웃하면 그대로 보이지 않습니다.
> 이 문서는 **누가, 어떤 상황에서, 어떤 화면을 어떤 순서로 지나가는가**만 다룹니다.
> 시스템 구조는 `docs/system-design.md`, 시장·경쟁·수익모델은 `docs/service-plan-wisor-2026-08-18.md`에 있습니다.

**등장인물을 새로 만들지 않았습니다.** 기획서 §10.1의 네 세그먼트를 그대로 씁니다.
두 문서가 사용자를 다르게 정의하기 시작하면 어느 쪽도 근거가 되지 못합니다.

| 다루는 것 | 다루지 않는 것 |
|---|---|
| 실제 라우트와 컴포넌트를 지나가는 순서 | 화면 디자인·문구 시안 |
| 각 단계에서 시스템이 실제로 하는 일 | 아직 만들지 않은 기능의 흐름 |
| 시나리오가 끝나는 지점 | 전환율·퍼널 목표치 (기획서 §14.2) |
| 사용자가 막히는 지점 | 개선안 — 발견만 적고 고치지 않습니다 |

**시장 심리(`/learn/market-sentiment`) 시나리오는 없습니다.** 이 문서를 쓰는 중에 해당 기능이
저장소에서 제거됐습니다(`docs/HANDOFF.md` 2026-08-18 · 시장 심리 기능 제거). 화면·계산 모듈·수집기·
생성 JSON이 모두 빠졌고 상단 메뉴 항목도 사라졌습니다. **없는 화면의 시나리오는 쓰지 않습니다.**

**시나리오를 읽는 법** — 여섯 칸이 반복됩니다.

| 칸 | 뜻 |
|---|---|
| 상황 | 사용자가 이 화면에 오기 전에 겪고 있던 것 |
| 진입 | 첫 화면과 그 경로 |
| 화면 순서 | 실제 라우트. 화살표는 사용자가 누르는 것 |
| 시스템에서 일어나는 일 | 그 순간 어느 코드가 무엇을 하는가 |
| 끝나는 지점 | 시나리오가 종료되는 상태 — **전부 확인 사항에서 끝납니다** |
| 막히는 지점 | 지금 코드에서 실제로 걸리는 곳 |

## 1. 등장인물

기획서 §10.1의 우선순위를 그대로 따릅니다.

| 순위 | 세그먼트 | 이 사람이 Wisor에 오는 이유 | 담당 시나리오 |
|---|---|---|---|
| **1** | 미국 주식 2~5년차. 추천을 따라가 봤고 결과가 엇갈린 사람 | 왜 샀는지 스스로 설명하지 못한다 | S1 · S2 · S6 |
| **2** | 가치투자 스터디·독서모임 참여층 | 책의 원칙을 오늘의 종목에 대보는 단계가 수작업이다 | S3 · S4 |
| 3 | 금융권 취업 준비생 | 지표는 외웠는데 실제 기업에 적용해 본 적이 없다 | S5 |
| 4 | 이제 막 시작한 초보 | 용어부터 막힌다 | 현재 전용 시나리오 없음 |

1번이 규모와 동기를 함께 가진 유일한 층이라(기획서 §10.1) 시나리오도 1번에 가장 많이 배정돼 있습니다.

## 2. 시나리오

### S1. 이미 들고 있는 종목의 근거를 뒤늦게 찾는다 — 세그먼트 1

**상황**
남이 추천한 종목을 샀다. 지금 수익이 났든 잃었든, 왜 샀는지를 자기 말로 설명하지 못한다.
증권사 앱은 가격과 차트만 보여주고, 커뮤니티는 결론만 말한다.

**진입**
홈이 아니라 **종목 상세가 첫 화면입니다.** 검색 유입이 이 시나리오의 기본 경로입니다
(기획서 §10.2 — 435개 정적 페이지가 유입 자산인 이유).

**화면 순서**

```
검색 → /stocks/AAPL
       → 기준 막대에서 판정 하나를 확인한다
       → 우하단 해설 버튼 (전역)
       → '나의 학습노트' 렌즈
       → /learn/masters/buffett/3   (검증 — 사기 전에 무엇을 확인하는가)
```

**시스템에서 일어나는 일**

| 단계 | 동작 |
|---|---|
| 페이지 진입 | 빌드 시점에 이미 만들어진 정적 HTML. 서버가 `lib/scores.ts`에서 읽어 props로 내려보낸 값이고, 재무데이터 전체는 브라우저로 가지 않습니다 |
| 렌즈 전환 | `StockLenses`가 `기업 관점` / `나의 학습노트` 두 렌즈를 오갑니다. 같은 화면에 도구와 기록이 함께 있습니다 |
| 해설 버튼 | `PersonaChatFab`은 `app/layout.tsx`에 **전역 마운트**돼 있어 어느 화면에서든 뜹니다. 경로에서 티커를, `?style=`에서 모델을 읽습니다 |
| 예열 | 마운트 시 `getHealth()`를 한 번 던져, 사용자가 본문을 읽는 동안 챗봇 서버가 깨어납니다 |
| 질문 전송 | 프론트는 `{ticker, persona}`만 보냅니다. 지표 값은 서버가 `scores.json`에서 직접 읽습니다 |
| 노트 저장 | `lib/store.ts`의 `saveNote()` → 비회원은 임시 localStorage, 회원은 Supabase `study_notes` |

**끝나는 지점**

AAPL 화면에서 사용자가 보는 것은 **8개 기준 중 7개가 판정됐고 그중 6개를 충족**했다는 사실과,
`이자 감당력`은 판정할 데이터가 부족해 `unknown`으로 남았다는 표시입니다(데이터 신뢰도 `보통`,
가격 기준일 2026-08-12 · 재무 기준일 2025-09-27).

여기서 시나리오가 끝납니다. 화면은 살지 말지를 말하지 않고, **다음에 무엇을 확인할지 한 줄이 남은 채**
끝납니다. 학습노트의 두 번째 칸이 그 자리입니다 — "다음 실적에서 무엇을 확인할지".

**막히는 지점**

- 첫 화면이 종목 상세라, 이곳이 학습 서비스라는 걸 모른 채 점수만 보고 나갈 수 있습니다. 홈으로 가는 길은 상단 워드마크뿐입니다.
- `unknown` 기준을 본 사용자가 "그래서 이건 어디서 확인하나"를 물을 곳이 화면에 없습니다. 해설 챗봇이 받아주지만, 그 연결을 화면이 안내하지는 않습니다.

### S2. 기준으로 후보를 좁힌다 — 세그먼트 1

**상황**
종목을 고르는 자기 기준이 없다. 남의 목록 말고 **왜 이 순서인지 보이는 목록**을 원한다.

**진입**
상단 메뉴 `종목 찾기`. 이 링크는 항상 `/screener/buffett`로 고정 진입합니다(`components/Nav.tsx`).

**화면 순서**

```
/screener/buffett
  → 철학별 채점 종목 수 비교표를 본다
  → 모델 전환 (buffett · graham · lynch · greenblatt)
  → 목록에서 종목을 누른다 → /stocks/[ticker]?style=buffett
  → 관심종목에 담는다 → 다시 목록으로
```

**시스템에서 일어나는 일**

목록은 세 덩어리로 나뉩니다. 이 분리가 이 화면의 핵심입니다.

| 덩어리 | 뜻 |
|---|---|
| 점수 산출 종목 | 모델별로 다릅니다 — Buffett 312 · Graham 289 · Lynch 250 · Greenblatt 244 (380종목 중) |
| 정보 부족 | 판정에 필요한 데이터가 모자라 **점수를 만들지 않은** 종목. 억지로 계산하지 않습니다 |
| 판정하지 않은 업종 | 데이터가 아니라 **모델이 맞지 않는** 쪽. 눌러서 지표는 그대로 볼 수 있습니다 |

정렬 UI는 없습니다. `ScreenerCompanies`가 고정 순위로 50개씩 보여주고 `더보기`로 늘립니다.
각 행에는 `CriteriaBar`와 함께 충족 사유 2개·확인 사항 1개가 미리 붙습니다.

화면 위쪽 `CoverageTable`은 철학별 기준 수·채점 종목 수·정보 부족 수를 한 표로 보여줍니다.
이 표는 `/learn/scoring`과 **같은 `Coverage` 값**을 씁니다. 숫자를 두 곳에서 따로 세면 반드시 어긋나기 때문입니다.

현재 이 흐름에서 남기는 이벤트는 관심종목을 추가할 때의 `watchlist_added`입니다.

**끝나는 지점**

관심종목 목록이 생깁니다. 화면이 스스로 말하듯 **"순위는 결론이 아니라 살펴볼 순서"**이고,
목록 하단에는 데이터 생성 시각과 함께 매수 권유가 아니라는 문장이 붙습니다.

**막히는 지점**

- 메뉴에서 들어가면 언제나 버핏입니다. 다른 모델은 화면 안에서 한 번 더 눌러야 만납니다.
- 피셔·막스·소로스가 없는 이유는 화면에 적혀 있지만, 그 세 철학의 학습 화면으로 가는 링크가 이 화면에서 이어지지 않습니다.
- 종목 검색창이 없습니다. 특정 종목을 찾으려면 목록을 넘기거나 URL을 직접 쳐야 합니다(§4 참고).

### S3. 대가 한 명을 다섯 장으로 통과한다 — 세그먼트 2

**상황**
책은 읽었는데 원칙이 손에 잡히지 않는다. 스터디에서 쓸 공통 교재가 필요하다.

**진입**
상단 메뉴 `배우기`.

**화면 순서**

```
/learn  → 일곱 대가 카드 (MasterGrid)
  → /learn/masters/graham        업적 · 원칙 · 출처 · 5장 경로
  → /learn/masters/graham/1      전제
       읽기 → 확인 n개 → 정리
  → /learn/masters/graham/2 …/5  탐색 · 검증 · 처분 · 실패
```

**시스템에서 일어나는 일**

한 장은 `chapterSteps()`가 만드는 스텝 열로 펼쳐집니다 — `읽기` 하나, 문항 수만큼의 `확인`,
마지막 `정리`. 장마다 문항 수가 달라 스텝 수도 달라집니다.

`MasterPath`에는 **잠금이 없습니다.** 모든 노드가 항상 눌립니다. `완료`는 저장된 진도에서 오고
`다음`은 진도가 없는 첫 장입니다. 순서를 강제하지 않고 인지만 시킵니다.

문항은 세 계층이고 **정답이 있는 것만 채점합니다**(기획서 §4.1).

| 계층 | 사용자가 받는 것 | 저장 |
|---|---|---|
| 채점형 | 즉시 정오 + 풀이 | 정답률 (`recordQuiz`) |
| 첨삭형 | 점수 없이 "빠진 요소" 안내 | 축별 태그 |
| 기록형 | 없음. 3개월 뒤 재노출 | 프로필 원본 (`saveJournalEntry`) |

모든 문항을 마치면 `master_lesson_completed` 이벤트를 남깁니다.

일곱 대가가 **같은 다섯 장**을 공유하는 것이 이 시나리오를 성립시킵니다.
그레이엄의 `처분`과 린치의 `처분`이 같은 자리에 있어야 비교가 가능합니다.

**끝나는 지점**

다섯 장 완료 상태가 `/me`에 남습니다. 종목 화면으로 넘어가지 않아도 시나리오는 완결됩니다.

**막히는 지점**

- 기록형 문항의 "3개월 뒤 재노출"은 **`/me`를 다시 열었을 때만** 계산됩니다. 알림이 없습니다(§4 참고).
- 진도 초기화(`resetMasterProgress`)는 대가별 경로 화면에만 있습니다.

### S4. 두 철학을 같은 칸에서 맞대 본다 — 세그먼트 2

**상황**
그레이엄과 린치를 각각 읽었다. 이제 **같은 질문에 두 사람이 뭐라고 답하는지** 나란히 보고 싶다.

**진입**
`/learn` 화면 안. `MasterGrid`의 `#compare` 점프 링크가 같은 페이지 하단의 비교표로 데려갑니다.

**화면 순서**

```
/learn
  → #compare 점프
  → StyleComparisonTable : 일곱 철학 × 다섯 칸
  → StyleComparisonPicker 로 볼 철학·칸을 고른다
```

**시스템에서 일어나는 일**

비교표는 `/learn` 하단에 **임베드**돼 있습니다. `/learn/compare`는 같은 표(`asPageHeading`)에
`CROSS_EXERCISES` 최종 기록 문항을 더한 별도 라우트로 남아 있습니다. 최종 기록에는 다음 장이
없어 이어가기 버튼이 비활성화됩니다.

**끝나는 지점**

일곱 철학의 같은 칸이 한 화면에 놓인 상태. 어느 철학이 옳다는 결론은 나오지 않습니다.

**막히는 지점**

**`/learn/compare`로 들어가는 링크가 하나도 없습니다.** `apps/web` 전체에 이 경로를 가리키는
`Link`가 없고, `#compare` 앵커는 `/learn` 안의 섹션으로 갈 뿐입니다. 비교표 자체는 `/learn`에서
볼 수 있으므로 사용자가 잃는 것은 **그 라우트에만 있는 최종 기록 문항**입니다.
`/learn/compare`는 빌드되고 서버 렌더도 되지만, 화면을 눌러서는 갈 수 없습니다.

### S5. 이 점수를 믿어도 되는지 따진다 — 세그먼트 3

**상황**
지표는 외웠다. 그런데 이 서비스가 내놓은 점수가 어디서 왔는지 확인하지 않으면 쓸 수 없다.

**진입**
스크리너 화면 안의 `점수는 어떻게 만들어지나` 버튼.

**화면 순서**

```
/screener/[style] → /learn/scoring    기준 · 임계값 · 가중치 · unknown 처리 · 철학별 채점 범위
                  → /screener/[style] 로 되돌아간다

/learn            → /learn/sources    커리큘럼 근거 자료 (별도 경로)
```

**시스템에서 일어나는 일**

`/learn/scoring`은 점수가 블랙박스가 아님을 보이는 화면입니다. 기준마다 임계값과 가중치가
`scores.json`의 `styles`에 그대로 들어 있고 화면이 그것을 읽습니다. 하단 `CoverageTable`은
스크리너와 같은 값을 쓰고, 각 철학 이름이 다시 `/screener/[styleId]`로 이어집니다.

`/learn/sources`의 각주는 원문·정리·창작으로 태깅되고, 정합성 검사가 **빌드 시점에** 돌아
어긋나면 빌드가 멈춥니다.

**끝나는 지점**

판정 근거를 확인한 상태. 이 사용자가 다음에 하는 일은 대개 S3(커리큘럼)입니다.

**막히는 지점**

- 스크리너와 `/learn/scoring`은 양방향으로 이어졌지만, **`/learn/sources`는 여전히 떨어져 있습니다.** `/learn`과 대가 개요에서만 들어가고, 근거를 따지는 사용자가 있는 `/learn/scoring`에서는 갈 수 없습니다.

### S6. 며칠 뒤 다시 온다 — 전 세그먼트

**상황**
지난주에 노트를 남겼다. 그때 뭘 확인하겠다고 적었는지 기억나지 않는다.

**진입**
상단 메뉴 `내 학습`.

**화면 순서**

```
/me
  → 투자 대가 챕터 진도
  → 퀴즈 결과
  → 관심종목  → /stocks/[ticker]
  → 학습노트  → 상태를 바꾼다
  → 다시 볼 기록  (90일 지난 기록형 문항)
```

**시스템에서 일어나는 일**

서버 컴포넌트는 관심종목 카드에 필요한 이름·업종·가격·시가총액·기준일 요약만
클라이언트로 내려보냅니다. 재무데이터 전체가 이 화면 때문에 브라우저로 나가지 않도록 한 경계입니다.

`MyLearning`이 마운트되면서 `getProgress` · `getWatchlist` · `getNotes` · `dueJournalEntries`를
`lib/store.ts`에서 읽습니다. 비회원은 브라우저 임시 기록, 회원은 사용자별 RLS가 적용된
Supabase 기록을 사용합니다. 인증 직후 임시 기록은 계정 기록과 병합되고 성공 후 로컬에서
제거됩니다. `dueJournalEntries(afterDays = 90)`는 `isDue()`로 기록 시각이 90일 경계를
지났는지 판정합니다.

학습노트 상태는 다섯 가지입니다 — `처음 확인` · `추가 조사 필요` · `학습 완료` · `관찰 중` · `관심 제외`.
전부 학습 진행 상태이고 보유·매매 상태가 아닙니다.

**끝나는 지점**

노트 상태가 갱신되고, 90일이 지난 기록형 문항에 지금의 답을 덧붙인 상태.
**과거의 자기 판단과 지금의 판단을 나란히 보는 것**이 이 화면의 목적입니다.

**막히는 지점**

- 비회원 임시 기록은 현재 브라우저에만 있습니다. 가입하거나 로그인해야 다른 기기에서 이어집니다.
- 90일 재노출은 사용자가 `/me`에 들어와야만 계산됩니다. 들어오지 않으면 영원히 뜨지 않습니다.

## 3. 시나리오 × 화면 커버리지

기획서 §4의 화면 목록을 기준으로 맞춰 봅니다.

| 화면 | 경로 | S1 | S2 | S3 | S4 | S5 | S6 |
|---|---|---|---|---|---|---|---|
| 홈 | `/` | | | | | | |
| 배우기 | `/learn` | | | ● | ● | ● | |
| 대가별 학습 | `/learn/masters/[slug]` | | | ● | | | |
| 학습 장 | `/learn/masters/[slug]/[chapter]` | ● | | ● | | | |
| 철학 비교 | `/learn/compare` | | | | ◐ | | |
| 점수 설명 | `/learn/scoring` | | | | | ● | |
| 출처 | `/learn/sources` | | | | | ● | |
| 종목 찾기 | `/screener/[style]` | | ● | | | ● | |
| 종목 상세 | `/stocks/[ticker]` | ● | ● | | | | ● |
| 내 학습 | `/me` | | | ● | | | ● |
| 해설 챗봇 (전역) | `PersonaChatFab` | ● | | | | | |

`◐` — 시나리오가 그 화면의 내용에는 닿지만, **그 경로로는 들어갈 수 없습니다.**

이 표에서 나오는 것 세 가지입니다.

1. **`/learn/compare`에 온전히 도달하는 시나리오가 없습니다.** 비교표는 `/learn`에서 볼 수 있으니 사용자 가치가 통째로 사라진 건 아니지만, 그 라우트에만 있는 최종 기록 문항은 지금 아무도 만나지 못합니다. 시나리오를 지어내 채우지 않고 그대로 둡니다 — 링크가 없다는 사실이 기록되어야 할 것이지, 가려야 할 것이 아닙니다.
2. **`/learn/sources`는 S5에만 나오고, 그 S5 안에서도 다른 화면과 이어지지 않습니다.** 근거를 따지는 사용자층(세그먼트 3)은 기획서에서 광고 가치가 낮다고 본 층이라 유입 경로에서 먼 것 자체는 의도와 어긋나지 않지만, 화면끼리 끊긴 것은 별개 문제입니다.
3. **해설 챗봇은 전역 마운트인데 시나리오는 S1 하나입니다.** 어느 화면에서나 열 수 있지만, 종목 상세 밖에서는 사용자가 챗봇 안에서 종목을 직접 검색해야 대화가 시작됩니다.

## 4. 아직 시나리오가 성립하지 않는 것

쓰고 싶었지만 **지금 코드에서 거짓이 되는** 흐름입니다. 여기 적힌 것을 시나리오로 옮기려면 코드가 먼저 바뀌어야 합니다.

| 성립하지 않는 흐름 | 왜 | 근거 |
|---|---|---|
| 3개월 뒤 "그때 이렇게 답했습니다" 알림을 받는다 | `dueJournalEntries(afterDays = 90)`는 `/me`를 열었을 때만 계산됩니다. 푸시·메일·배지가 없습니다 | `apps/web/lib/store.ts`, `apps/web/lib/journalDue.ts` |
| 종목명을 검색해 바로 상세로 간다 | 웹 화면에 검색 입력이 없습니다. 종목 검색은 **해설 챗봇 안에만** 있습니다(`searchCompanies`) | `apps/web/components/PersonaChatFab.tsx` |
| 관심종목 점수가 바뀌면 알려준다 | 점수는 배치가 커밋해야 바뀌고, 화면은 빌드 시점 정적입니다. 변화 감지 주체가 없습니다 | `docs/system-design.md` §4.2 |
| 시장 심리를 과거와 비교해 본다 | 2026-08-18에 화면·데이터·수집기가 모두 제거됐습니다 | `docs/HANDOFF.md` |
| 한국 주식을 본다 | 유니버스가 S&P 500 + NASDAQ-100 중복 제거 517종목이고, 그중 380종목이 실렸습니다 | `apps/web/lib/generated/scores.json` |
| 피셔·막스·소로스로 종목을 걸러 본다 | 일부러 점수화하지 않았습니다. **점수화할 수 없는 것을 점수화하지 않는 것도 제품의 입장입니다** | 기획서 §4.2 |

마지막 줄은 미완성이 아니라 결정입니다. 위의 일곱 줄과 성격이 다릅니다.

## 5. 이 문서를 쓰며 확인한 것

**모든 시나리오가 확인 사항에서 끝납니다.** 매수·매도 판단으로 끝나는 흐름은 하나도 없고,
그렇게 끝나도록 화면을 이어붙일 수 있는 경로도 찾지 못했습니다. 종목 화면의 마지막 요소는
항상 "다음에 무엇을 확인할지"이거나 기준 판정이고, 그다음 칸은 비어 있습니다.

**날짜가 화면마다 붙습니다.** 종목 상세는 가격 기준일·재무 기준일·모델 버전을, 스크리너는
데이터 생성 시각을 함께 표시합니다. "현재"로 적힌 곳은 없었습니다.

**시나리오와 시스템 경계를 검증하며 남은 불일치 한 건**입니다.

| 불일치 | 실제 | 오래된 쪽 |
|---|---|---|
| 기획서 §4의 화면 목록에 `/learn/compare`가 있습니다 | 페이지는 빌드되지만 **들어오는 링크가 하나도 없습니다.** `.ts`·`.tsx`·`.mjs`·`.json`까지 넓혀 찾아도 빌드 산출물(`.next*`)과 `StyleComparisonTable`의 주석 한 줄뿐입니다 | **저장소**입니다. 문서가 아니라 링크가 빠졌습니다 |

**직접 확인한 수치** — 버핏 8개 기준, 모델별 산출 종목 수(312 / 289 / 250 / 244), 380종목,
가격 기준일 2026-08-12, AAPL의 판정 7개·충족 6개·`unknown` 1개는 `apps/web/lib/generated/scores.json`에서
읽었고 기획서와 일치했습니다. 198문항·435 페이지는 `docs/HANDOFF.md`의 검증 기록을, 35장은 기획서 §4.1을 인용했습니다.

2026-08-26에는 챗봇 변환표에 `magicFormulaRoc` → `magic_formula_roc` 매핑을 추가해
관련 계약 테스트까지 통과하도록 바로잡았습니다.
