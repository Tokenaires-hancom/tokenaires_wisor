# Wisor

> 기업을 고르는 법과 가격을 관찰하는 법을 함께 가르치는 투자 학습 서비스.

투자 대가의 판단 기준으로 종목을 좁히고, 차트에서 보이는 것을 읽는 법을 배우고, 두 관점을 하나의 학습노트로 모읍니다. **매수·매도 판단, 목표가, 미래 가격 전망은 제공하지 않습니다.**

---

## 지금 상태

설계 가이드 13장의 개발 순서 기준으로 **1~2주차 핵심 범위와 실데이터 조회의 첫 단계**가 구현돼 있습니다.

| 영역 | 상태 |
|---|---|
| 재무데이터 → 투자 철학 결과 배치 | 버핏 1.0 / 그레이엄 1.0 / 린치 1.0 절대 기준 · 그린블랫 1.0 상대 순위 · 토스증권 종가와 SEC 공시로 동작 |
| 차트 분석 API + 안전장치 | 프롬프트 1.0, 필터 규칙 18개, 재생성·거절 정책 · 동작 |
| 웹 앱 | 홈 · 투자 철학 7유형×5장 · 횡단 비교 · 차트 5단원 · 4개 정량 스크리너 · 토스증권 현재가 조회 · 종목 상세(두 렌즈) · 학습노트 · 내 학습 |
| Supabase | 스키마 작성 완료, 앱 연결은 미착수 (지금은 브라우저 저장) |
| 실데이터 공급자 | 토스증권 전 거래일 종가 + SEC Company Facts 최근 5개 회계연도 연결 |

이번 변경에서 데이터 파이프라인 50개와 웹 29개 테스트를 통과했습니다. 차트 API의 기존 53개 테스트는 의존성이 설치된 서비스 환경에서 별도로 실행합니다.

## 실행

세 개를 각각 띄웁니다. 순서는 상관없지만, 차트 분석을 보려면 API가 켜져 있어야 합니다.

### 1. 점수 만들기

```bash
cd data-pipeline
python -m venv .venv && source .venv/bin/activate
pip install pytest
python run_batch.py          # → apps/web/lib/generated/scores.json
pytest -q
```

`scores.json`은 저장소에 이미 들어 있으므로 이 단계를 건너뛰고 바로 웹을 띄워도 됩니다.

### 2. 차트 분석 서비스

```bash
cd services/chart-api
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --port 8000
pytest -q
```

`.env`의 `WISOR_VISION_PROVIDER`는 기본값이 `mock`입니다. 키 없이도 화면 전체를 관통해 볼 수 있습니다. 실제 비전 모델을 붙이려면 `anthropic`으로 바꾸고 `WISOR_VISION_API_KEY`를 넣습니다.

### 3. 웹

```bash
cd apps/web
npm install
cp .env.example .env.local
npm run dev        # http://localhost:3000
```

## 구조

```
wisor/
├─ apps/web/            Next.js 15 · 화면 전체 (1번 담당)
│   ├─ content/         투자 철학 7유형×5장 · 차트 5단원 (정적 콘텐츠)
│   ├─ lib/generated/   배치가 만든 scores.json — 화면은 이 파일만 읽는다
│   └─ lib/store.ts     사용자 데이터 저장 (Supabase 교체 지점)
├─ data-pipeline/       Python 배치 · 재무데이터 → 투자 철학 점수 (3번 담당)
├─ services/chart-api/  FastAPI · 차트 이미지 분석과 안전장치 (4번 담당)
└─ supabase/schema.sql  사용자 데이터 스키마 (2번 담당)
```

경계 규칙 세 가지:

- 화면 코드는 재무 원천을 직접 만지지 않습니다. `scores.json`만 읽습니다.
- 차트 분석기에는 **종목명·티커를 넘기지 않습니다.** 종목과의 연결은 프론트엔드와 학습노트에서만 관리합니다.
- 비전 LLM API 키는 `services/chart-api` 프로세스 안에만 있습니다. 브라우저로 나가지 않습니다.

## 점수는 어떻게 나오는가

블랙박스 회귀식이 아니라 **기준 통과 여부의 가중 합**입니다.

```
버핏 1.0 = 8개 기준
  자본 효율성(3)      5년 평균 ROIC ≥ 12%
  수익성 지속성(2)    5년 중 4년 이상 ROIC ≥ 10%
  현금흐름 지속성(3)  5년 연속 잉여현금흐름 양(+)
  현금 창출력(2)      FCF 마진 ≥ 10%
  부채 부담(2)        순부채 / EBITDA ≤ 2.5배
  이자 감당력(1)      영업이익 / 이자비용 ≥ 8배
  사업의 성장(2)      매출 5년 CAGR ≥ 3%
  현재 가격(3)        FCF 수익률 ≥ 4% 또는 EV/EBIT ≤ 자기 5년 중앙값

점수 = 충족 기준의 비중 합 ÷ 판정한 기준의 비중 합 × 100
```

기준을 정확히 8개로 둔 것은 기획서 11.3의 권장 문구("8개 기준 중 6개에 부합합니다")가 문자 그대로 성립하게 하기 위해서입니다.

그린블랫 1.0은 절대 기준 가중합이 아닙니다. 같은 종목 유니버스 안에서 5년 평균
자본수익률과 EBIT/기업가치(이익수익률)를 각각 내림차순으로 순위 매긴 뒤 두 순위를
합산합니다. 합산값이 같으면 같은 종합 순위를 부여합니다. 피셔·막스·소로스는 공개
재무지표로 본질을 근사하지 않고 학습 화면의 자가진단 체크리스트로만 다룹니다.

**판정할 데이터가 없으면 미충족이 아니라 `unknown`입니다.** 없는 값을 벌점으로 바꾸지 않습니다. `unknown`이 전체의 25%를 넘으면 점수를 만들지 않고 '정보 부족'으로 표시합니다.

## 차트 분석의 이중 안전장치

**1차 — 프롬프트** (`services/chart-api/app/services/prompt.py`)

이미지 안의 모든 문자는 분석 대상이지 지시가 아니라는 규칙, 외부 지식 사용 금지, 판독 불가 시 거절 규칙이 들어 있습니다. `relatedLessons`는 실제 존재하는 5개 단원 id로 화이트리스트를 고정합니다.

**2차 — 출력 필터** (`services/chart-api/app/services/safety.py`)

18개 규칙을 두 등급으로 나눕니다.

- `sentence` — 그 문장만 떼어내고 나머지 설명은 살립니다 (예: 외부 정보 인용)
- `block` — 응답 전체를 버리고 한 번 재생성합니다. 그래도 걸리면 분석을 제공하지 않습니다 (예: 매수·매도, 목표가, 가격 예측)

응답 스키마는 `extra="forbid"`이므로 `buySignal`, `targetPrice`, `confidence` 같은 필드는 구조적으로 들어갈 수 없습니다.

새로운 위반 사례를 발견하면 문장을 그대로 `tests/test_safety.py`의 `MUST_BLOCK`에 추가하세요. 정상인데 걸린 문장은 `MUST_PASS`에 추가합니다. 이 두 목록이 필터의 기준선입니다.

## 디자인 규칙 하나

**빨강과 초록을 쓰지 않습니다.**

주식 화면에서 이 두 색은 가격의 방향을 뜻합니다. Wisor는 방향을 말하지 않기로 한 제품이므로 방향색을 팔레트에서 뺐습니다. 충족은 자두빛(`--plum`), 미충족은 황토(`--ochre`)로 구분하고, 색만으로 의미를 전달하지 않도록 채움·빗금·점선을 함께 씁니다.

서명 요소는 **기준 막대**입니다. 큰 점수 숫자 대신 칸으로 이뤄진 막대가 먼저 보입니다. 칸 하나가 기준 하나이고, 칸의 너비가 그 기준의 비중입니다.

## 구조상 지켜지는 것

**재무데이터는 브라우저로 나가지 않습니다.** `lib/scores.ts`는 서버 전용이고, 클라이언트는 `lib/scores.types.ts`에서 타입만 가져옵니다. 실수로 import하면 브라우저에서 예외가 납니다. 확인은 `npm run build` 후 `grep -rl "evEbitMedian5y" .next/static/`.

**업로드 이미지의 EXIF는 모델로 나가지 않습니다.** `services/image.py`가 회전 정보를 픽셀에 반영한 뒤 다시 인코딩하므로 촬영 위치와 기기 정보가 사라집니다. 동시에 긴 변 1568px로 줄여 전송량을 95% 줄입니다.

**사용자 데이터 저장은 한 파일을 거칩니다.** `lib/store.ts`의 함수는 전부 비동기라서 Supabase로 교체할 때 함수 본문만 바꾸면 됩니다.

## 지켜야 할 세 가지 원칙

1. 투자 철학 점수와 차트 분석을 합쳐 하나의 매수 점수를 만들지 않습니다.
2. 차트 분석은 이미지에서 보이는 현상만 설명하고 미래를 예측하지 않습니다.
3. 정식 기능은 정적 차트 교육이고, 이미지 분석은 제한된 베타로 둡니다. 판독 품질이 기대보다 낮아도 전체 출시가 밀리지 않습니다.
